# 生产衔接对照学习（plan-comparison-v2）

> 本版本为历史实验，已由 [plan-improvement-v3](plan_improvement.md) 替换。请使用新文档中的命令。
> **实验结论：本版不宜继续长训练。** `plan_compare_trial` 的 100 轮实验出现明显退化；见 [结果复盘](plan_compare_trial_review.md)。下方命令保留用于复现，不作为新的训练建议。

训练入口：`plan-train`。推理入口：`plan-agent`。

**发现更好的接法 → 从相同状态执行对照 → 网络学习选择 → 用受保护对照经验复习。**

这版替换原来的整局投资 PPO。它会更新神经网络权重；候选分支用来生成学习标签，不是将参数搜索结果当作模型。没有 DECEM 源码或训练标签，也不声称复现其训练算法。

## 每个环节如何落地

| 环节 | 实现 |
|---|---|
| 生成候选 | 新投入与现有生产的后继安排：新增小麦／胡萝卜批次后接另一种生产；当前一组同类地格收获 1 或 2 次后接作物或动物。保留原有新增、暂缓、购地候选作为参照。 |
| 完整执行 | `Controller` 保存地格、当前生产、后继生产、收获次数、备料及执行状态；当前生产继续服务，临近转换时采购，到货后才改变生产目标。既有路线及已选接续不会被后面的普通候选覆盖。 |
| 兑现确认 | 实际库存增长确认收获，真实地格确认后继开工，后继的实际收获确认产出。失败、资金等待明确记录。对照收益来自整局结束的真实现金。 |
| 执行对照 | 每局只在少数决策点复制完整模拟状态、双方执行器和路线。原选择沿基准对局继续，替代选择在副本中运行到终局。双方继续使用相同的冻结网络／规则，但每一步根据分支观察重新决策。 |
| 网络学习 | 同一个观察下仅比较两个**实际测试过**的候选。胜／平／负优先；赛果相同用终局 `(我方现金−对方现金)/(双方现金绝对值之和)` 区分。相对差小于 0.002 不生成强弱标签。 |
| 保留选择 | 初期／中期／后期 × 三种对手来源 × 九种后继类别，共 81 个固定桶，每桶最多 4 个高价值对照；近期池单独保留 512 个。近期样本不能直接挤占历史优秀名额。 |

### 执行边界

- 一次选择为最多 4 个地格承诺一段两阶段接续；后继产出后释放这段承诺，网络可再接下一段。不是一次指定整季固定计划。
- 例如“小麦收获→备好的胡萝卜续种→胡萝卜收获”，或“小麦回款→购买牛→腾地养牛”。后者若钱未到账，采购会等，不会把预计收入当作现金。
- 对已有作物不会提前清掉未成熟植株。正在执行的路线先完成；如果原路线已经续种，转换会等待这轮成熟。
- 畜牧转作物使用游戏已有的“停止喂养后退出、空场再清理转产”机制；不捏造出售活体／瞬间回收成本。仍可收集退出前已有产品。
- 备料占用会约束后续新增投资；已有生产的必要服务仍优先。容量仍是简化的工人负荷约束，未实现完整跨日排程求解器。
- 路线构造、基础雇工、买料执行及销售仍由现有 Rust 规则执行；本次学习对象是生产衔接选择，未同时开放独立买卖择时网络。
- 模型只读取双方可见生产、市场及自己的私有资源。完整状态仅由训练模拟器用于分支；对手隐藏库存与未来种子不进入网络输入。

### 学习与探索

网络输入沿用 320 维观察，32 维候选特征采用新约定，包含当前／后继品种、批量、时间、现金、服务负荷等。候选的第 30 维恒为零，**没有旧版 75% 默认方案偏置**。零初始化时通过排序平手选择可执行规划器，之后直接用网络分数确定性选择。

基准对局使用当前网络的确定性行为，使其访问局面与上线方式一致。探索在复制状态的替代分支发生：一半机会优先抽取接续候选，其余覆盖全部合法候选。新模型会改变下一轮到达的局面，再在那里比较新接法。

每个有效对照只含两个方案。较好方案目标概率 0.9，另一方案 0.1；不将未测方案全标错。使用成对交叉熵更新策略网络，原 critic 不参与该损失。新对照与受保护对照在**同一个 loss、同一次 Adam 更新**中学习，不再先 PPO 再另做一次“很小权重”的独立 Adam 更新。

每轮检查新对照和历史优秀对照的排序准确率。如果更新使任一准确率下降超过 5 个百分点，恢复该轮更新前的网络和 Adam；新发现仍进经验池。没有用“初始动作不能改变”来锁死学习。

对手沿用固定规划器、近期冻结模型、冠军模型，配对种子交换座位。每次评估后更新近期快照。这里没有再叠加新的 PFSP 机制。

历史对照是**当时冻结后续策略下的结果证据**，不是对所有后续策略都成立的最优标签。长期保留与新策略的冲突需要从回退率、保留准确率和独立评估里观察；本实现不能保证收益单调上升。

## 构建

本机 cargo 不在 PATH 时先设置：

```bash
export PATH=/tmp/route-rl-rustup/toolchains/stable-x86_64-unknown-linux-gnu/bin:$PATH
export CARGO_HOME=/tmp/route-rl-cargo
cargo build --manifest-path native/Cargo.toml --release --features train --offline \
  --bin plan-train --bin plan-agent -j 4
```

Rust 运行模拟／采集，原生 LibTorch 在 CPU 推理、CUDA 更新。分支会增加模拟量；不通过重复空算来制造 GPU 满载。

## 新实验：100 轮

在 screen 内运行，必须使用新目录。**不加旧版 `--resume`，旧 PPO 检查点不兼容。**

```bash
mkdir -p runs/plan_compare_trial
native/target/release/plan-train \
  --out runs/plan_compare_trial \
  --iterations 100 \
  --games-per-update 16 \
  --branch-points 2 \
  --alternatives 1 \
  --workers 7 \
  --device cuda \
  --epochs 8 \
  --batch-size 64 \
  --learning-rate 0.0003 \
  --eval-every 10 \
  --eval-games 8 \
  --seed 1200 \
  --eval-seed 1100000000 \
  > runs/plan_compare_trial/train.log 2>&1
```

100 轮 = **1,600 局完整基准对局，最多 3,200 条剩余赛季分支**，另加验证。分支共享起点前的历史，不能都算作全新 720 回合对局；日志记录实际 `simulation_steps` 和 `equivalent_full_games`。`--iterations` 表示额外更新轮数。

`--branch-points` 为每局最多比较的决策点（1–4），`--alternatives` 为每点替代方案数（1–2）。增加它们首先增加 CPU 仿真量。默认先用 2 × 1，避免重新变成全局穷举。

`--eval-games 8` 为每种对手 8 局：初始评估 16 局；例行当前模型与冠军各面对固定规划器和当时冠军，共 32 局；有希望晋级再追加独立种子 32 局。评估不进入训练。当前固定评估集用于比较趋势，晋级复核使用轮换新种子，小样本晋级仍不等于稳健提升。

## 输出与判断

- `comparisons.jsonl`：每次实际对照的起点、双方现金、两个具体计划、后继开工／产出／失败状态、是否存在有效收益差。先确认发现的接法确实兑现。
- `metrics.jsonl`：`decisive_pairs`、`better_alternatives`、`update.pair_accuracy_before/after`、`update.retained_accuracy_before/after`、`update.reverted`、`weights_changed`、实际模拟量／耗时。排序正确率反映这些已测试对照的学习情况，不代表未见局面泛化。
- `evaluations.jsonl`：确定性完整对局的现金、胜负、后继产出次数。`candidate.by_opponent.0` 为固定规划器，`.1` 为当时冠军。
- 训练日志的 `opponent=0/1/2` 分别为固定规划器／近期快照／冠军；与评估的编号含义区分开。
- `latest.json`：最新网络、Adam、随机状态、配置、冻结对手、经验池、下一批种子及累计模拟量；每轮原子保存。
- `best.json`：通过确定性胜负初筛及独立种子复核的冠军；初始化即存在。
- `initial.json` 与 `checkpoint_XXXXXX.json`：起点和每次评估轮完整状态。

要看到的闭环是：有正收益替代方案出现 → 网络更常选对这些对照 → 后续仍保留 → 确定性新对局收益／胜率改善。仅权重变化、loss 下降或者链接数增加都不算完成这个目标。

## 同版本续训

```bash
mkdir -p runs/plan_compare_long
native/target/release/plan-train \
  --resume runs/plan_compare_trial/latest.json \
  --out runs/plan_compare_long \
  --iterations 500 \
  --games-per-update 16 --branch-points 2 --alternatives 1 \
  --workers 7 --device cuda --epochs 8 --batch-size 64 \
  --eval-every 10 --eval-games 8 \
  > runs/plan_compare_long/train.log 2>&1
```

续训恢复已保存的学习率、种子、对手与经验；始终使用新输出目录。该命令说明操作方式，不代表已经验证值得长训练。

## 实现检查记录

库与训练入口共 75 项测试通过，包括真实引擎上的“收获→后继种植→后继收获”、现金不足不产生采购、隐藏对手库存不改变网络输入、相同分支选择复现终局、成对排序改变确定性选择、优秀经验不被近期覆盖、完整检查点恢复。

最小 CUDA 检查记录在 `runs/plan_compare_impl_smoke`：6 局基准、12 条分支，产生 12 组有效对照，其中 5 个替代方案更好；8 次梯度更新，旧口径排序准确率 0.50→0.667（旧统计把初始平手记为半分，不能据此认定确定性选择改善），`weights_changed=true`、`reverted=false`。真实分支包含作物→动物、动物→作物的后继产出，也记录了未完成的接续。该检查用于确认数据—执行—学习连通，不作为泛化或比赛实力提升证据。

正式实验应使用上面的新目录从头训练，不续训实现检查目录。
