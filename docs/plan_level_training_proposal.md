# 从经营计划学习：下一阶段实现与训练方案

状态：完整设计仍未全部实现；生产衔接对照学习已落在 [plan-comparison-v2](plan_comparison.md)，具体已完成范围以该文档为准。依据 `competition_replay_review.md`，不声称这是 DECEM 的训练算法。保留原生 Rust 运行、独立 actor/critic；farm2945 继续只作外部验证，不要求移植源码或使用它生成训练标签。

## 1. 核心改变

当前已经有项目和路线两个层级，因此仅把它重新命名为分层 RL 不够。当前 Project 主要记录生产类型及落实状态，Route 主要安排当天工作；下一版本要增加可检查的**投入、未来服务义务、产出窗口和资金占用**。

学习单位是选择或修订一个经营计划。多个计划可以同时执行；遇到新回款、土地释放、服务不足、公开需求改变时，策略可以增加、缩减、转产或退出。不能等一头牛全季结束才允许下次决策，也不能把整季锁成一张动作表。

系统流程：

```
公共观察 + 自己的库存/现金 + 已承诺计划
  → 生成多种可执行经营候选
  → 网络比较候选的长期效果
  → 更新计划与资源预约
  → Rust 调度器执行实际动作、检查回执
  → 有新机会或计划失效时重新选择
```

当前时段的可执行性使用硬约束；未来收益与供给使用注明假设的估计，不能假装已知。未来预计销售款不算已到账现金。

## 2. 计划对象与模块

以下为拟新增/修改的接口，不是已存在的代码。

| 模块 | 职责 |
|---|---|
| `pipeline/plan.rs` | Plan、地块变更、所需材料、服务时间窗、资源预约、完成/取消条件 |
| `pipeline/capacity.rs` | 现金、种子、饲料、仓储、人员与可达工作时间联合检查 |
| `pipeline/planner.rs` | 生成批量开局、补种、扩养、转产、退出等候选；路线保留多种经济方向 |
| `pipeline/encoding.rs` | 编码每个候选的商品产出、净投入、回款时间、工时及不确定性 |
| `pipeline/executor.rs` | 材料到账和动作成功确认；预约释放、局部修复、续接；不随探索反复毁约 |
| `pipeline/trading.rs` | 执行库存/资金目标与有时效的交易计划；成交后更新事件基准 |
| `pipeline/rollout.rs` | 记录经营决策时刻、实际经过时间、执行结果和真实采样概率 |
| `learning/policy.rs`、`experience.rs` | 计划选择、受限能力保持、分模块更新预算、完整更新检查 |

Plan 至少包含：

- 计划编号、涉及的地格及目标生产；相关工人的服务窗口。
- 当前需支付现金和材料，已确认库存与待成交请求分开。
- 每种商品的预计交付量与时间，未来喂养/浇水等义务。
- 相关销售/采购参数：保留量、需筹现金、可用交易资金上限、有效期。
- 继续、完成、缩减、转产、取消条件；后续实际回执。

预计产出和价值用于比较候选；奖励来自真实对局结果，不能用自己的预测利润给自己发奖励。

## 3. 把回放思路写成可组合能力

1. **批量开局与扩张**：候选涵盖不同作物/畜牧组合和批次大小。按实际资金与服务容量决定规模，替代每天2项目、固定25%现金限制；保留计算预算上限，防止搜索爆炸。
2. **连续作业**：作业图表达取料→服务→收肥→施肥→收获→补种→返仓的依赖，附近作业按容量和时间窗插入路线。并非每条路线都必须混种养。
3. **动态用途**：空地和即将释放的地块能接不同生产；转产同时检查清理、建设、购买、运输和后续服务。
4. **市场适应**：根据公开商店、市场历史、双方可见成熟窗口和自己的已承诺产出，生成不同供给/价格假设。对手种植不代表确定时间、数量的出售。
5. **季末退出**：只承诺仍有机会兑现的生产；根据实际库存、现金需求安排销售和服务退出。

候选筛选同时保留高预计收益、早回款、低资金占用、不同商品/布局等方向；不能先按工作次数只留下三条，再期待网络恢复被删掉的方案。

## 4. 训练分三阶段

### A. 用自己的规划器生成有效起点

先实现一个基于保守经济估计的确定性计划选择器，确保规划能力能形成完整生产链。然后在 Rust 完整对局中搜索它的参数：开局组合、服务强度、扩张预算、转产门槛、库存目标等。

第一版用简单的候选参数群体：保留数个稳定高收益且经营不同的配置，对它们做小幅参数变动，用相同种子/座位/冻结对手进行配对比较。搜索的是观察条件下运行的经营规则，不是从引擎隐藏种子或对手私有状态求出的逐步最优动作。

可以从16个参数配置×4个训练种子×双座位的一轮128局开始；这是工程起始规模，不是已经验证的最佳超参数。后续轮换训练种子，确认集和最终测试集不用于生成训练标签。

将经过复现的几种配置的计划选择用于初始化网络，保留不同需求环境下的不同方案。一次盈利局中的每个动作不自动成为正标签；初始模仿只是起点，不能代替后续改进。

### B. 在完整经营计划上做 RL

网络按当前状态和候选计划打分：训练时按分布采样，提交时确定性选取完整计划。策略探索批次、品种、转产与服务强度，底层调度器执行已经承诺的可行工作。

- 现有生产继续运行；探索在有新机会或合理修订条件时发生。
- 有效计划可以保持到完成，也可以因缺料、资金、市场变化局部修订，取消本身的成本计入真实结果。
- 记录 `(状态, 候选集合, 选择, 实际采样 logp, 经过时间, 实际结果)`。
- PPO 只用当前采样策略的数据；过去精英轨迹与确定性探测轨迹使用单独的辅助项，不伪装成 on-policy 数据。
- 回报按决策间真实时间累计。宏决策数量改变后，不能直接沿用每条样本同样的折扣/trace 衰减。
- 多计划共享现金与市场，不能把后来全场卖货收入都记成某一头牛的功劳。对局回报用于策略梯度，计划账本用于诊断和辅助预测。

生产启动阶段可沿用真实现金回报。进入正式对抗训练后，明确切换到终局胜负目标（胜+1、平0、负−1）；现金/交付量可作独立价值预测或诊断，不叠加“工作越多越好”的奖励。目标转换单独记录、单独实验，不能偷偷换奖励后把前后 loss 当同一指标。

价值网络保持与策略网络独立。对手池在一个训练区间内冻结，保留近期、历史弱点和少量覆盖；暂不重新发明联赛。

### C. 生产稳定后，训练交易调整

第一版交易使用需求约束和稳定执行：兑现已承诺材料、保留运营现金、按库存与回款计划交易。自由投机与生产采购分开分配资金，避免把养护资金全花掉。

随后固定生产策略，训练单独市场参数或策略：销售目标库存、分批数量、成交顺序、供给变化后的提前调整、有限额的额外库存。交易后先更新实际状态基准，再判断新的外部机会；避免自己的订单无限重新触发自己。

第一版生产与市场各自更新参数；仅增加输出头但仍共用可更新编码器不能实现冻结。市场有所增益后再以明确预算交替微调。无需从一开始同时学习每一笔交易和每个工人动作。

## 5. 让改进进入确定性策略并被保留

- 保留的是“状态条件下经过复现的计划选择/分布”，而非无条件记住某商品总赚钱。
- 精英筛选考虑对手来源、市场环境、配对改进和执行完成；不只按绝对现金排序。
- 在训练更新中加入小权重的成功计划学习，以及成功状态上的冻结参考 KL；精英保持项不能完全被当前 critic 归零。
- 参考应在可靠改进后更新，只约束代表性的成功状态，给新状态和新计划留空间。
- 生产、路线、交易设置各自抽样和更新预算；交易决策变多不自动获得六倍更新份额。
- 检查 PPO 和辅助项全部完成后的策略偏移、关键计划选择和确定性执行。小 KL 不等于 argmax 一定不变。
- 明显破坏性的更新可拒绝或减小步长；回滚策略需要同步处理优化器状态，不能只改权重而沿用不匹配的动量。

示意损失：`L_PPO + α L_success + β KL(reference || policy)`；critic 独立训练。α、β、偏移阈值需要小实验确定，本方案不宣称一组固定系数可保证收敛。

部署候选与探索中的 learner 分开：探索中的模型允许暂时失败；通过新种子、换座、多个冻结对手对照的版本才替换提交候选。这提高交付稳定性，不能替代 learner 本身的保持机制，也不能提供真实胜率单调提升的数学保证。

## 6. 比赛前的最小实现范围

先完成 A 所需的批量计划、资源约束、按商品的路线价值和确定性执行。使用 Rust 仿真做有方向的计划参数搜索，保留当前可用模型作对照。若规划器本身还不能兑现高质量经营，暂时延长 PPO 没有意义。

在此基础上再完成 B 的计划级学习与保持；市场独立学习放在 C。新的动作/特征契约需要新版本，旧检查点不保证兼容，不应通过修改 schema 冒充迁移成功。

本方案借鉴的是强回放的可执行结构。它允许比观察到的模板更好的组合被发现，但上限仍受候选生成覆盖限制；后续发现的高收益配置需要进入候选库，模板不能永久写死。

## 方法依据与边界

- 时间延伸动作、执行策略及终止条件：Sutton 等 [Intra-Option Learning](https://icml.cc/Conferences/1998/papers/paper162.html)。这里的经营计划是针对本项目的设计，不是论文直接给出的农场方案。
- PPO 使用当前交互数据优化代理目标：[PPO](https://arxiv.org/abs/1707.06347)。不会因为换成计划动作就自动保证收敛。
- PPO clip 不严格保证信赖域及性能稳定：[Truly PPO](https://arxiv.org/abs/1903.07940)。引用其问题分析，不声称采用本文方案即可获得其理论条件下的保证。
