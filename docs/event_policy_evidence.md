# 事件策略：修正证据筛选偏差

> 本文记录历史v6实验。当前v7输入尺度修复和命令见[event_policy_normalization.md](event_policy_normalization.md)。

当前训练格式：`event-policy-iteration-v6`。执行契约仍是 `event-shared-policy-season-scope-v5`：本次不改变经营候选、事件范围、账本、路线、确定性执行规则。

## 先复盘，再确定改动边界

已复核 `competition_replay_review.md`、`plan_compare_trial_review.md`、`event_plan_pair_overnight_review.md`、`event_policy_fresh_trial_review.md` 及当前实现。DECEM回放支持条件性续产、转产、物料和现金周转的行为目标，不能证明对方算法。

fresh前33轮不是继承失败事件权重，6次候选初筛全部退步。第30轮首次安排recent中54条改动更好、112条更差；elite则54条更好、22条更差。原分桶按胜出方案的品种：不同改动成功可占多个桶，保持原安排胜出都挤进同一类别。按gain保留强样本还改变了持平样本比例。随后固定份额重放，却没有纠正这种结果依赖的选择。

这解释了一个明确的数据偏差，尚不能认定解释了全部退步。

### 复查中撤回的方案

最初准备新增“每局最多修改一批”的硬限制。再次对照用户目标后撤回：它限制的是整局经营能力，不能等同于限制一次网络更新的幅度；持续保留这个限制也没有给已学会能力继续累积的路径。因此本轮不同时引入新的生产次数规则。

原有范围仍是四段赛季的收获机会，各自至多一次同批次后续修订。这个范围由此前协议确定，本轮既不扩大也不缩小。单点对照与多个选择组合之间仍可能有相互影响，必须通过整套独立对局验收；不能声称采样修正就保证解决这个问题。

## 实际修改

1. **与结果无关的历史蓄水池抽样。** 当前参考策略版本内，所有实测比较以相同概率进入最多2048条的历史样本；再保存最近512条完整记录。抽样只使用到达序号与独立、可恢复的随机数状态，不看赢家、胜负差大小、品种或正负号。不中断记录中的失败和持平证据，不人为把胜负凑成1:1。
2. **取消胜出方案决定经验类别。** 比较记录的品种标记改为被测试备选的品种，仅作诊断，不再控制名额。
3. **沿用同一个胜负回归目标。** 更新仍混合新数据、历史数据和近期数据，名义比例50%/25%/25%；这表达对当前采样与历史/近期采样的混合，绝非对所有经营局面的无偏分布承诺。新样本中的首选优先采样、探索采样仍存在；此次消除的是结果依赖筛选。训练没有增加现金奖励、成功样本加权或产量奖励。
4. **记录更新后的实际首选。** 在本轮已采集的完整候选集合上，按唯一局面复算argmax：保持、实测更好、实测更差、未实测分别记录；未实测的选择不能算成功。这是训练局面的诊断，不是独立泛化成绩。下一轮采集原本就优先执行当前网络不同于参考的首选，此机制保留。
5. **参考与部署保护继续有效。** 不晋级就不刷新参考网络或清空有效数据；完整候选独立复核通过后，才整体替换部署并清除依赖旧继续策略的活动标签。未晋级时基础现金不变是正常口径。

历史样本随机抽样不能保证某个罕见成功永不被移出内存；原始JSONL仍保留所有证据，已验收网络负责保留已通过整局验证的能力。不能用只留下成功记录来代替能力保护。

## 对照历史失败的检查

| 历史问题 | 本轮对应约束 |
|---|---|
| market3高频交易挤占学习 | 没有新增买卖动作、交易触发或交易样本 |
| plan_compare局部学习直接接管整局 | 基础采集仍是已验收策略；候选范围和完整验收保留 |
| 后续网络反复刷新，旧标签失效 | 继续版本只在晋级后变化 |
| 成功经验保护变成偏向成功的监督 | 按与结果无关的随机抽样保存成功、失败和持平 |
| 权重变化或局部loss下降冒充变强 | 新增完整候选首选实测覆盖；最终仍看独立对局胜负 |
| 日初缺工、后续事件被普通配额吞掉 | 沿用已修正的真实维护观察与同批次事件保护 |
| 为防止乱改而封住经营能力 | 撤回新增的“一局一批”限制，执行契约不变 |

## 实验命令

从已验收的v3底座开始新的事件网络。不要继承失败的提议权重；旧运行和文件保留。先100轮，另开新目录：

```bash
export PATH="/tmp/route-rl-rustup/toolchains/stable-x86_64-unknown-linux-gnu/bin:$PATH"
export CARGO_HOME=/tmp/route-rl-cargo
cargo build --manifest-path native/Cargo.toml --release --features train --offline \
  --bin event-train --bin event-agent -j 4

mkdir -p runs/event_policy_evidence_trial
native/target/release/event-train \
  --out runs/event_policy_evidence_trial \
  --base-checkpoint runs/plan_improvement_trial/best.json \
  --iterations 100 --games-per-update 16 --workers 7 --device cuda \
  --branch-points 2 --alternatives 2 \
  --branch-steps-per-game 1440 --max-branches-per-game 4 \
  --epochs 8 --batch-size 64 --learning-rate 0.0003 \
  --eval-every 5 --eval-games 8 --confirm-games 16 \
  --seed 220000 --eval-seed 1860000000 \
  > runs/event_policy_evidence_trial/train.log 2>&1
```

`iterations`是额外更新次数；100轮含1600局基础轨迹及预算内终局分支，另有评估。没有启动用户的这轮训练。

新v6检查点可用`--resume .../latest.json`在另一个目录完整恢复，包含Adam、经验库的随机状态、有效标签和待复核候选。

旧v5的`deployment`保持原执行含义，`event-agent`兼容读取。训练入口拒绝把旧的winner筛选bank冒充均匀抽样后的bank。旧原始比较的物理含义没有因本轮改变；重建完整抽样历史需要从原始JSONL重放，不能只拿旧精选子集重新命名。本轮命令选择新学习器和新数据，保留已验收底座。

### 重点指标

- `fresh_outcomes`、`history_outcomes`、`recent_outcomes`：分别按首次安排/后续修订显示更好、更差、持平及平均标签。不同时间分布可有波动，不能要求完全一致，但不应再由赢家桶制造结构性倾斜。
- `post_update_choices`：更新后首选的保持次数、实测覆盖、未知次数、实测收益方向。只在本轮训练局面计算，不能作晋级依据。
- `evaluations.jsonl`：候选相对参考的实际比赛得分、独立复核、是否晋级。现金只诊断。

本轮检验的是纠正监督偏差之后，网络能否更准确地区分何时保持、何时调整。不承诺长训必然收敛，也不把连通测试当作经济提升证据。

## 本次验证结果

- 训练入口11项、部署入口4项、事件及资源执行28项，共43项定向测试通过；release构建通过。
- 临时目录`/tmp/event_evidence_v6_smoke_20260928`完成2轮CUDA连通运行：8局基础轨迹、20条终局对照，其中8条后续修订；后续实际合法候选数20–50，没有退化成只剩保持/取消。
- 20条记录全部进入尚未满额的历史库和近期库，包括3条改善、2条退步、15条持平。两轮均更新权重；参考版本维持0。首轮相同种子/座位/对手的4局基础轨迹报告与原v5运行逐字段一致。
- 第2轮候选初筛得分差为-0.25，正确拒绝晋级。此微型运行仅证明连通及保护机制，不能据此判断训练改善或收敛。
