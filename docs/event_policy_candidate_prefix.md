# 在候选实际后续状态上学习经营选择

本次训练格式为 `event-policy-iteration-v8`；采集契约为 `candidate-prefix-local-and-sequence-v1`。默认执行范围仍是四个赛季阶段的首次安排，各自一次同批次修订。旧已验收部署保留原执行契约。

## 写代码前的结论与边界

已复核 `competition_replay_review.md`、`plan_compare_trial_review.md`、`event_policy_mechanism_review.md`、normalized 第20轮及192局独立评估。区分以下三层：

- **实测：**9次不同修订都选择了较小的小麦候选；4次单独执行就使平局变输，另5次不改变胜负。它们来自有限种子，不能推断所有缩量都不好，也不能把主要责任归给多个调整互相破坏。
- **代码限制：**原采集主要来自冠军轨迹；探索首次安排之后最多补一次条件修订。网络对自己连续选择造成的状态覆盖不足。旧训练920条比较中713条不改变胜负，不能用删除持平或失败经验解决稀疏信号。
- **尚待验证：**补上候选实际状态和连续段证据，是否能改善条件化选择及独立整局得分。连通测试、loss和参数变化都不能回答这一点。

当前底座已有批次生产、经济路线、共享材料与工时、两阶段转换；示例局续种199次、收获到续种中位数1步。DECEM五场对应183–222次、中位数同为1步；还观察到条件转产、材料共用与现金周转。这些支持经营行为目标，不能证明DECEM的训练算法，不能再套用旧mixed的生产规模限制。

本轮没有增加交易动作、改变胜负目标、重做对手池或放宽晋级门槛。

## 采集、标签、执行和验收

每轮更新前冻结一份候选和已验收冠军，保存完整策略快照。一个训练条件使用同一随机种子、座位和对手，分别运行冠军与候选至step719。

1. **冠军证据继续采集。** 保留原冠军状态的单次修改和条件探索；不让未验收候选替代全部基础数据或历史对手。
2. **新增候选前缀证据。** 候选通过与部署相同的 `Deployed::prepare/execute_choice` 实际完成之前的选择。只保存真正到达的局面；现金、库存、工人、路线占用及计划承诺均来自真实状态。
3. **在同一前缀分支。** A保持当前安排；B执行当前首选修订，若首选就是保持，则探索另一个实际合法候选。A/B从相同世界状态与双方策略记忆开始，之后都交给同一冻结冠军运行至终局。候选整局结果绝不冒充A的终局。标签仍只有 `score(B)-score(A)`，胜1、平0.5、负0。
4. **独立记录连续段。** C执行候选当前首选，并让同一候选处理这个scope已拥有批次及其部分替换产生的后续事件；其他scope及段外后续由同一冻结冠军负责。A/B/C全部到终局。如果不可能再出现候选负责的后续修订，C直接复用与其完全相同的已完成分支。C不会生成额外的局部训练标签；不能把整段结果摊给其中每次动作。
5. **整套策略仍需独立验收。** 保存候选完整轨迹相对冠军的结果，但这批训练种子的得分不能用于晋级。原来的同种子换座初筛、冻结候选、多次预定独立复核继续使用。正在训练的网络不会替换待复核候选。

这里的“冠军继续”包括从候选前缀继承的真实批次身份和策略记忆；后续选择权重、范围规则和对手版本均明确冻结。局部标签回答这个条件下单次修改的效果，不声称已经求出了候选自身全部未来选择的价值。C补充同批次的连续安排证据；最终完整候选是否变强，仍由独立对局判断。

采样优先覆盖实际后续修订，存在首次安排和修订时也覆盖首次安排。冠军/候选前缀的预算优先级按种子和轮次轮换，与结果无关。历史库继续使用与结果无关的蓄水池抽样，保留改善、退步和持平；没有赢家专属名额。

## 模拟预算

默认每个训练条件有2条完整轨迹，最多8条额外终局分支、4320个额外step，两项预算同时生效。候选局部对照至少需要2条后缀；需要测连续段时为3条，启动前一次性确认完整预算，不截断比赛补标签。冠军分支共享同一预算。

所以每个训练条件最多 `1438+4320=5758` 个模拟step；下方8个条件/轮最多46064步，约64.1局完整模拟工作量，另加独立评估。`games-per-update`现在表示成对的训练条件数，实际基础轨迹数是其两倍。增加的模拟用于真实新状态和独立段证据，不能把更多样本本身称为能力改进。

## 分阶段扩大责任

- `--followup-scope single`：先在原接管范围学习，默认不扩大。
- `--followup-scope batch`：须显式从**本次v8协议已独立验收通过**的检查点初始化。`scope_confirmed`只在独立复核晋级后写入；原v7历史晋级不能绕过这一阶段。
- 扩展后，同一网络持续处理已拥有批次的真实可修改事件。保持会保留责任；部分替换同时保留未改部分和新部分的归属；取消或后继承诺全部落实后停止。它不自动把后来的新作物世代或无关地块纳入管理。
- 四个首次安排scope不扩张，底座仍负责开局、大部分扩张、维护和具体路线。这里扩展的是已有批次尚未落实部分的后续选择，不是接管全局。
- 扩展候选使用新执行契约 `event-shared-policy-batch-lineage-v8`。采集、连续段、完整评估和最终部署读取同一个范围字段；未通过完整独立验收，旧部署保持原契约。
- `--resume`不允许改变范围。扩展必须另开输出目录初始化，不自动发生；先检查单次选择与整局成绩，再决定是否启动扩展阶段。

执行约束沿用真实维护后的观察；不虚构下一天工人，不在真实持续短缺时禁用取消。路线受阻的已拥有事件优先于普通scope，并保留到原批次可编辑。新批次契约额外跟踪部分替换的两支，避免遗漏剩余地块或借用无关批次。

## 初始化、恢复与旧数据

- `--warm-start v7_or_v8_latest.json`：保留已验收部署、历史对手，以及归一化提议网络的权重。新协议重建Adam、活动标签库、待复核候选，轮次从1开始；不是完整resume。适合继续修正已定位的第20轮网络。
- `--init-from old_checkpoint.json`：保留已验收部署及历史对手；对旧v5–v7使用新归一化提议网络。若来源已有v8独立验收记录，则继承其已验收归一化权重，便于下一阶段沿用已学行为。
- `--resume v8_latest.json`：完整恢复网络、Adam、活动经验、抽样状态、冻结待复核候选、种子游标及范围；仍须新输出目录。
- 旧运行和原始比较文件都保留。初始化不会只删除失败标签，也不把旧记录改名伪装成候选前缀证据；新采集协议下重新积累活动标签。新标签显式记录采集契约、继续策略修订号、继续执行契约、来源快照和真实终局结果。晋级使继续策略改变时，旧活动标签失效。
- `event-agent`仍可读取v4–v7已验收部署；读取v8时也只看`deployment`。目标范围字段和未验收网络不会改变部署。
- v7的`--evaluate-checkpoint`和单次修订只读诊断继续可用；不能用v7训练检查点直接resume。批次阶段的完整对局使用`--evaluate-checkpoint`，旧四臂单次范围诊断不用于批次阶段。

## 先运行20轮实验

从项目根目录执行。该命令沿用第20轮归一化提议权重，保留其已验收部署，采用新采集协议；不继承旧标签或Adam。训练和评估种子与本次连通测试分开。不要写入旧实验目录。

```bash
export PATH="/tmp/route-rl-rustup/toolchains/stable-x86_64-unknown-linux-gnu/bin:$PATH"
export CARGO_HOME=/tmp/route-rl-cargo
cargo build --manifest-path native/Cargo.toml --release --features train --offline \
  --bin event-train --bin event-agent -j 4

mkdir runs/event_policy_candidate_prefix_trial && \

  --out runs/event_policy_candidate_prefix_trial \
  --warm-start runs/event_policy_normalized_continue/latest.json \

  --iterations 20 --games-per-update 8 --workers 7 --device cuda \
  --branch-points 2 --alternatives 2 \

  --eval-every 5 --eval-games 8 --confirm-games 16 \
  --seed 280000 --eval-seed 1950000000 \

```

## 看哪些证据

- `metrics.jsonl`：`candidate_prefix_pairs`、`candidate_revision_pairs`、`candidate_coverage`。合法候选最小/最大数、只剩Keep/Cancel的数量、没有修订的候选轨迹、实际有后续事件的段，帮助检查是否真的补到了需要的状态。`training_sequence_score_gain`只作训练分布诊断。
- `comparisons.jsonl`：`source=candidate_prefix`是候选真实前缀；原来的`accepted_trajectory`、`conditional_exploration`仍在。`full_row`是完整合法候选输入，参考和备选有实际双方终局现金；训练只从这些现金计算胜负得分。
- `sequences.jsonl`：候选完整决策轨迹、完整对局结果和`same_prefix_segments`的A/B/C实际终局结果。`local_target=false`、`promotion_evidence=false`，不会给每个动作摊派整段收益。
- `collection_sources/collection_*.json`：每轮冻结候选、冠军继续策略、两类模型对手和配置。比较记录通过`source_snapshot`定位；resume继承的旧记录对应来源目录里的同名文件，manifest保留恢复路径。
- `evaluations.jsonl`：完整候选独立初筛与复核；是否晋级以这里为准。待复核期间`candidate_iteration`可能早于当前训练轮次。

先检查候选状态中“保持与缩量”的实际胜负方向和覆盖，再看独立整局验收。若覆盖不足或独立得分仍退步，应继续定位，不以loss下降、生产次数或训练段得分代替经营改进。

## 本次实际验证

- 事件、资源、输入编码相关31项测试通过；训练入口15项、部署入口5项通过。新增测试用实际引擎核对候选采集与部署终局一致、单次分支可重算、完整段不进入单次监督、预算不够时不启动对照。测试中的固定生产偏好只用于走通真实事件，不进入训练策略。
- 在 `/tmp/event_candidate_prefix_smoke_20260929` 完成第1轮；中断后从其保存点恢复到 `/tmp/event_candidate_prefix_resume_20260929`，完成第2轮及小型评估。合计6个训练条件、32条对照，其中12条候选实际前缀对照、10条候选后续修订，另有2段包含真实后续事件的A/B/C记录。
- 候选后续修订的实际合法候选数为17–26，未出现只剩Keep/Cancel。两轮模拟step为10308、21349，分别低于2个/4个条件的预算；分支数14、32，均在上限内。
- 第20轮归一化提议权重、原deployment和历史对手在初始化时逐字段保留；恢复初始检查点与来源latest逐字段一致。旧原始检查点SHA-256未改变。32条记录逐条检查了冻结来源、继续契约、真实终局得分方向、前缀归属及A/B/C的共用结果。
- 第2轮小型初筛得分改善，但独立复核只有1个种子，`p=0.5`，按原协议保留冻结候选继续复核，**没有晋级**；已验收修订号保持1。此结果只验证了采集、更新、恢复和验收保护机制，不能证明实力提升。
