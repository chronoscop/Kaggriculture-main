## 1. 单次错误已经存在，不能把原因全归给组合

| 模式 | 得分率 | 平均现金 |
|---|---:|---:|
| 已验收策略 | 70.83% | 58079.79 |
| 只换首次安排 | 75.00% | 57761.63 |
| 只换后续修订 | 62.50% | 57981.63 |
| 首次安排和修订都换 | 75.00% | 57702.00 |

两端模式的24局终局双方现金，与上次实际部署评估逐局完全一致，确认诊断没有另造执行规则。核对记录 `runs/event_policy_mechanism_review/verification.json`，原latest/best/metrics/evaluations/train.log哈希全部未变。

在已验收轨迹的70次后续决策中，新网络9次选择不同方案，全部将“两格下一批小麦”改为“一格”。分别只改变其中一次、其余保持旧策略到终局：

- 4条使得分由0.5变0，来自两个种子的换座对局；不能称为4个独立市场样本。
- 5条不改变胜负。
- 0条提高得分。

例：种子1890000000，对冠军，第205步缩减续种。旧策略终局80897:80897；只做该调整后77452:86280。种子1890000003有一条修订使自己现金增加，但对手增加更多，平局仍变输。

所以这批状态上已出现独立选择错误，不需要多个调整一起发生才退步。完整新策略得分没有低于“只换首次安排”：新安排改变了后续到达的状态，这些旧轨迹上的坏修订不再以同样方式出现。不能据此宣称普遍存在破坏性组合，也不能把两个模块的单独收益直接相加。

**样本边界：**4个种子只定位机制。此前32种子、每策略192局的结果仍是新网络71.88%、旧冠军73.96%，没有稳定超越证据；本次子集75%不能替代该结论。

## 2. 我们已经会连续干活，学习器改进经营的范围仍很窄

重新读取五场DECEM原始回放，并导出当前第20轮网络的完整逐步观察/行动（种子1890000000、座位0、对冠军）。按真实收获库存变化与成功种植统计：

| 行为 | DECEM五场 | 当前网络示例局 |
|---|---|---|
| 收获后成功续种次数 | 183–222 | 199 |
| 收获到续种间隔中位数 | 1步 | 1步 |
| 同一工人完成收获和续种 | 159–203次 | 141次 |
| 土地用途变化 | 作物间切换、作物转畜牧、部分畜牧退出后种作物 | 本局主要胡萝卜转小麦/羊、甜瓜转羊/胡萝卜 |

当前示例：第6天工人3，t151收获 → t152续种小麦 → t153浇水 → t159喂养 → t160照料 → t161收肥 → t164附近施肥 → t167返仓卸货。DECEM第10天工人12也能串起取饲料、喂养、收肥施肥、收获续种。

这说明当前执行层已有共享路线、物料接续和连续生产。不能套用旧market3的“只有十来块地、几乎不续种”诊断。不同种子/对手的回放不能用于现金排名；经营品种多也不是强度证明。上述路线按实际指令及状态检查，不把收肥后施肥的先后顺序当成逐单位肥料来源追踪。

代码边界：

- `event_policy::Version.scope=[0,1,2,3]`：每180步区间首个符合条件的收获安排，及其同批次一次后续修订；并非全场每次收获都由新网络安排。
- `plan_events::choices` 已有8种生产、1/2/4格批量、收获轮次、备料提前量和现金保留量，不能说没有可修订计划。
- 具体路线由 `plan_prototype::Agent` 调用 `economic_route_problem`，按经济价值与紧迫性固定筛选。此次学习器没有学习这些路线之间的选择。
- 本次新策略24局的后续选择为72次小麦、3次保持；首次安排72次小麦、21次保持、3次胡萝卜。经营基础较丰富，不代表新网络学会了更丰富的条件化经营。

**结构限制：**当前训练是在成熟的经营底座上学少数局部接法，尚不能靠这些更新全面改进扩张、服务布局和持续投资。有限接管原本是为了避免plan_compare的全局退化，不能直接删除限制；但也不应把它当成已经在训练整套灵活经营。

## 3. 学习数据的困难与尚不能断言的原因

当前20轮共920条比较：

| 类型 | 改善胜负 | 恶化胜负 | 胜负不变 |
|---|---:|---:|---:|
| 首次安排 | 33 | 82 | 377 |
| 后续修订 | 34 | 58 | 336 |

713/920，即77.5%，没有胜负差异。这不意味着标签错误；在这些真实对战中，小调整确实没有改变终局得分。但它们不能给出下一批如何安排的明确优劣方向。应保留胜、负、相同结果，不能再次只留赢家造成选择偏差，也不应偷偷改成现金奖励。

训练多数状态来自旧冠军；单次干预后也由旧冠军继续。这个标签准确描述“旧策略条件下这次改动怎样”，不保证候选网络连续干预后到达的新状态也被覆盖。当前分解实验显示这种条件依赖确实值得检查，但没有证明它解释了全部停滞。

输入归一化后，已有监测显示饱和问题解除。还不能凭这次9条分支，确定容量、优化器、特征缺失或数据稀疏中的哪一项占主导。已能确认的是：存在实测错误选择，训练信号多数不区分胜负，学习器对整体经营的控制范围有限。没有证据要求再次重做对手池或降低验收门槛。

## 4. 后续实施应形成同一个闭环

目标：让模型在自己造成的资源和生产状态下，学会继续、缩量、延期或转产；逐步扩大它能稳定负责的生产范围。

1. **在候选实际到达的状态上补对照。** 冻结一个候选，在现有获准范围运行，记录其首次安排之后的现金、物料、工时和生产承诺；在这些状态比较模型首选与保持原安排。一个局面内的各分支使用同一冻结继续策略，并给数据标记候选/参考版本。旧冠军状态的证据继续保留，但不能当成新条件已覆盖。
2. **同一批次的连续选择需同时保留单次与整段证据。** 比较原安排、单次修改以及候选后续修订构成的完整片段，实际运行至终局。整段有利不能给其中所有动作无差别贴正标签；只有分支支持的局部结论才能用于局部监督。不要重新引入周期自动更换的独立后续网络。
3. **先学清具体条件，再按生产批次扩大接管。** 从“两格何时应继续、何时应减一格”这种已发现的错误入手，覆盖充足与紧张的资源条件。之后让同一模型对完整批次的后续事件持续负责，扩大时同步扩大采集和整局验收。基础开局和未覆盖生产继续保留，不能一下接管整场。
4. **只以终局胜负推进已验收版本。** 失败保留旧部署；成功片段要成为可稳定选择的行为后，才扩大范围。独立确认、旧版本保护与执行账本继续有效。

这套改动的价值需要实验确认，不能承诺长训必然单调进步。它明确修的是“候选在自己的后续状态中做对连续选择”，而不是新增交易按钮、堆经验容量或仅提高晋级次数。本轮完成诊断与只读工具，尚未把这些建议改进训练。
