# contextual 前10轮：最后一次离线学习审计

## 结论

未发现足以支持“修正实现错误后继续长训”的证据。有效标签没有丢失、候选与标签对应、损失符号与梯度方向正确；当前学习器却没有从混合数据中学会有效调整的条件。固定数据上的进一步拟合及留出种子检查均未给出净收益改善依据。没有修改生产训练代码，没有新采集对局，没有替换模型或启动夜训。

## 输入与边界

- 固定读取 `runs/event_policy_contextual_overnight/checkpoint_000010.json`，避免随后台进程变化的latest。
- 320份完整菜单，80个训练种子；其中66份菜单存在优于参考的选择。
- 原始comparisons与经验库的320份full_row、候选顺序、终局现金逐项一致；66份有效菜单同时保留在history和recent。
- 初始模型、第10轮模型、best的SHA256在审计前后相同。
- 工具：既有Rust `event-menu-audit`；新增 `tools/audit_contextual_learning.py` 仅用于离线数学核对，未接入采集/部署。
- 所有输出位于 `runs/contextual_learning_final_audit`。额外拟合模型只存在于诊断进程内，未导出供部署。

## 逐项核对

1. 1532个非参考选项：119个改善、421个退步、992个持平，均按终局胜负差计算目标。66是存在有效选项的局面数，119是选项数。
2. 训练更新先对完整集合去重，每轮新数据全部参与8个epoch；去重保留一份Pair的evidence，其中仍包含全部候选的终局标签，不是只学习该Pair的一个替代项。
3. 损失为各有效候选 `(logp_j-logp_0 - (score_j-score_0))²` 的逐集合平均。log-softmax差等于logit差；候选0、掩码和方向均对应。所有候选group=1，部署没有被另一层分组选择覆盖。
4. PyTorch逐算子复算与Rust/LibTorch的320份候选概率最大绝对差 `2.98e-8`。
5. 119个正目标对应的logit梯度全部要求提高替代项相对评分；context、candidate、score权重均有非零梯度。最终公共score bias的梯度接近零是差值损失的正常性质。
6. 第10轮网络给119个有效选项的相对预测全部为负，范围约[-0.306,-0.022]，平均-0.171；在320份已见菜单上仍选参考317次，有效改选0次。

这支持“数据进入了学习，但还没有学出区分条件”，不支持“有效经验被全部筛掉”“梯度断开”或“晋级门槛吞掉了已学会的收益”。

## 能解释到哪里

多数替代项不优于参考，平均回归目标会支持保守选择；要改善必须学会那些少数局面中的条件差异。当前网络的表现符合先学会平均偏好、尚未学会有效例外的现象。不能仅凭标签比例认定它是唯一根因，也不能据此随意给胜例加权、改变比赛目标。

数据表征是否遗漏决定性条件、函数形式是否难以表达差异、优化预算是否不足、单次终局标签是否噪声较大，本次检查未能唯一归因。不能把其中某一个猜测再包装成已确认的修复。

因此保留原先的停止建议：没有找到值得用户再承担一轮训练成本的已验证修复。不改奖励，不放松晋级，不另开训练版本。
