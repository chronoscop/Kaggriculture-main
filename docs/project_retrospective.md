# Kaggriculture 项目收尾：尝试、教训与最终训练方法

本文用于归档与交接，不是新一轮训练提案。依据仓库实现、实验复盘和最后一次离线审计整理；早期没有独立报告的阶段按开发记录概述，不补造实验数字。

**结论：我们实现了较完整的生产执行与对照学习系统，也有局部和阶段性进步；但没有证明网络能稳定学会完整、连续、按条件调整的经营策略，更没有证明最终模型达到用户要求的 farm2945_resilient_response 对战标准。**

最后一次学习审计固定在 `event_policy_contextual_overnight/checkpoint_000010.json`。关于最终实验的数字只覆盖前 10 轮，不表示整个夜间训练已经完成。本次整理不修改检查点、不停止进程、不启动新实验。

## 1. 始终想实现的目标

比赛目标是 720 回合结束时比对手拥有更多现金：胜记 1，平记 0.5，负记 0。双方买卖会改变市场，因此绝对现金、产量和路线数量都不能直接代替胜负。

DECEM 回放提供的行为参照是：

- 当前生产持续回款，资源允许时分批扩张。
- 同一地块续种、转养、退出后重新种植，用途随条件变化。
- 工人沿一条路线服务多个地块和动物，衔接饲料、肥料、收获与返仓。
- 提前准备下一批物料，缩短收获后空档；资金不足时维持可行生产。
- 根据市场、剩余赛季、现金和工时，调整尚未执行的下一段安排。

例如：“先续种一轮小麦；现金、饲料和工时满足后转两格羊，否则继续回款，等条件变化再判断。”

回放证明这些行为存在，**不能证明 DECEM 使用了什么网络、搜索或 RL 算法**。我们尝试实现的是这些经营能力。[回放复盘](competition_replay_review.md)

## 2. 全部主要尝试与结果

### 2.1 采集、性能与 mixed 系列

| 阶段 | 尝试 | 结果与教训 |
|---|---|---|
| Python 路线采集、预训练 | `route_rl.pretrain` 示范采集与拟合，动态路线日志 | 采集昂贵；loss 下降不代表比赛能力提高。示范拟合、执行正确和经济收益需要分开检查。 |
| local_v4 | Keep 恒等性、固定作物替换、随机干预 | 检查了干预接口；“不报错”不能证明策略有效。 |
| Rust 加速 | 迁移模拟、采集、执行，使用 LibTorch CPU/CUDA 更新 | 主要链路成为 Rust；Python 保留于参考策略和离线分析。强 baseline 完整移植没有完成，后来将 farm2945 明确作为独立验证对象。 |
| mixed_v5 / v6 | 学投资和混合路线，先对规则对手训练 | 强制有路线就执行，仍不能解决投资层不启动生产；关闭等待不等于学会经营。弱对手也不足以衡量竞争力。 |
| mixed_v7 | 分类探索、匹配实际采样概率、区分随机训练与确定性执行，辅助学习成功轨迹 | 有早期进步，但更多尝试和路线不自动带来更多有效生产；必须检查确定性能力。 |
| 长训练、retention | 保留高收益、近期、多样性经验 | 曾在第 1885 轮后至 2700 轮没有新冠军。每类对手 32 个名额被多种经营方式分占，最后 96 局经验全部来自 2687–2700 轮；总容量约束抵消了长期保护。 |
| league / PFSP | 冠军、近期快照、历史战绩抽样、旧对手覆盖 | 改善了挑战来源，但经营方式不同不等于能暴露弱点，改对手池不能替代学习器改进。 |
| PFSP focus、独立网络 | 检查 PPO，拆开 actor/critic 表示，完善经验保护 | 诊断批次中，价值损失对共享层的梯度范数是策略损失的 13.4–41.2 倍，并有冲突方向；这是实际干扰，但不能断言解释全部退步。 |
| mixed_v8_market3 | 学习买卖时机、数量、顺序，补市场与对手公开供给信息 | learned 交易样本约占 77.6%，采集变慢；采购与生产需求脱节，交易又触发更多交易。rule 对照也不强，问题不只在市场动作。 |

这一阶段不是完全没有进步，但长期训练没有形成可靠的持续改善。旧 mixed 管线的项目数量、预算等限制不能套用到后来已有批量生产、两阶段转产的计划管线。

### 2.2 从逐动作学习转向经营计划

| 阶段 | 尝试 | 结果与教训 |
|---|---|---|
| plan_prototype | 批量生产、经济路线、两阶段转产，搜索计划参数 | 参数搜索可以找到配置，但不能称为网络学会条件经营。这次实现与用户要求的学习机制有偏离。 |
| plan_rl | 网络选择可执行计划，热启动后策略更新 | 权重和 loss 变化，没有可靠转化为确定性决策改善。 |
| plan_compare | 同状态替换一个计划，终局真实对照学习 | 用局部数据训练后让网络接管更大范围，破坏开局生产。采集范围、比较对象和部署范围不一致。 |
| plan_improvement | 固定窗口，小步验收，冻结已接受改进 | 第 35、40、55 轮接受 3 次改进，随后至 100 轮停滞。保留机制有效，但少量对照分散到多个窗口，未形成连续决策能力。 |
| event_plan | 批次身份、共享资源账本、经营事件、未来阶段修订 | 补了真实能力：调整尚未执行的下一批。但材料、资金、在途路线和到货约束必须进入真实执行，增加字段不等于完成。 |
| 胜负目标统一 | 删除“现金差改善种子必须更多”的晋级硬否决 | 修复了目标冲突。小幅胜负改善可以复核，证据不足仍不能直接晋级。 |
| event_plan_pair | 主安排与后续修订联合对照，补测网络首选 | 周期刷新继续策略导致主决策标签反复失效；后续经验挤占名额，分支模拟成本高。多个局部模块正确，不等于组合后的训练协议有效。 |
| event_policy | 固定完整参考策略和继续策略；有界整套候选验收后推进 | 数据条件和速度改善；首次安排与修订共用策略。未晋级不自动换继续策略，但稳定协议本身不能保证学会。 |

`plan_improvement` 固定面板从初始平均现金 51,912、得分率 50%，进到第 55 轮平均现金 52,519、得分率 87.5%。这里只有 4 个种子换座共 8 局，不能当作泛化胜率；后续没有持续推进。

`event_plan_pair_overnight` 从第 45 轮续到 196 轮，本段 151 次更新、30 次验收、0 次晋级。常规采集约 7 小时 22 分，网络更新累计约 54 秒。瓶颈主要是昂贵模拟和学习协议，不能归因于 GPU 没跑满。

### 2.3 条件判断、完整候选与最后审计

| 阶段 | 尝试 | 结果与教训 |
|---|---|---|
| fresh / evidence | 检查经验筛选，保留成功、失败、中性证据 | 原来按赢家品种分桶，使改动成功分散占桶、保持成功集中挤桶，产生偏差。修复后仍未学好；不能简单增加胜例权重。 |
| normalized | 修复输入尺度、tanh 饱和，版本化编码 | 网络必须有效使用状态；有梯度还不够。归一化后独立评估仍未证明稳定收益。 |
| candidate_prefix | 从候选自身真实轨迹取状态，对照固定继续策略 | 更接近部署分布，但仍有重复、中性比较；单次有利不保证连续组合有利。 |
| 离线可学习性检查 | 区分已知局面拟合、留出泛化和全菜单选择 | 已知局面能拟合，留出可能下降；两两比较准确不代表全菜单最高分选择有证据。 |
| complete_sets | 每份短名单全部终局对照，训练和部署使用同一菜单 | 消除了菜单内未测选项直接被选中的问题，但没有稳定晋级。相同输入有时对应冲突标签，暴露信息遗漏、部分可观测性或标签噪声问题。 |
| conditional | 保留延后方案，实现先续种、满足条件再转产 | 增加了经营表达，但有执行衔接冲突；能表达不等于知道何时有利。 |
| 收获交接修复 | 真实收获后交接，释放尚未执行的旧续种任务 | 8 个案例中后继产出地块从 5/11 到 10/11，但一场由胜转负。执行更可靠，不等于选择更有利。 |
| contextual v12 | 按资源、公开供需和续种机会筛选最多 6 个候选，完整对照 | 最后审计的前 10 轮存在有效接法，网络却几乎全部保持参考，没有学会有效调整条件。 |

## 3. 最终模型怎样工作

**网络在可执行的经营方案中选择；规则执行器把方案落实到采购、地块和路线。** 网络不会自由生成任意生产程序，也不直接决定每一步移动。

```text
可见局面：现金、库存、地块、工人、市场、对手公开生产
                  + 已有计划和未来承诺
                              ↓
经营事件：临近收获、物料到账、资源变化、服务延期
                              ↓
共享账本检查资金 / 物料 / 工时，生成有限可行候选
                              ↓
冻结底座提供参考，网络为菜单中的各项打分
                              ↓
在声明的接管范围内选择或修订下一段生产安排
                              ↓
执行器采购、组织混合路线、养护、收获、续种或转产
                              ↓
用真实执行回执更新账本，再处理后续事件
```

候选包括保持参考、继续生产、改变后继作物、小批转养、延后一轮和部分规模变化；contextual 菜单最多 6 项。预测价格、成本和时间用于筛选，不直接作为奖励。

已种作物、已付款物料和在途工作保留真实状态与成本；取消未来计划不能抹掉过去成本。未来销售款可以作为预测和启动条件，不能提前支出。

网络只在明确的事件范围改变行为，其他经营仍由已验收底座执行。批量生产、混合路线和转产能力并非全部由网络从零学会。

### 网络结构

最终事件模型是小型候选评分网络：局面特征与候选特征分别编码，合并后输出每项的标量评分；使用归一化输入和 tanh 隐层，掩码限制合法选项，确定性部署取最高分。

共享模块仍包含早期 PPO/价值网络代码，但**当前完整菜单训练学习的是候选相对评分，不是早期 mixed 管线的逐动作 PPO**。

## 4. 最终模型怎样训练

1. **冻结参考策略。** 一个周期内固定已验收版本及其继续策略，避免标签条件无故改变。
2. **采集真实状态。** 从参考和候选前缀实际执行到的经营事件取得局面，限定接管范围与模拟预算。
3. **完整菜单对照。** 同一状态分别执行各方案，之后按相同固定继续策略完成到终局。标签来自真实胜、平、负。
4. **学习相对得分。** 对候选 j 和参考 0，核心损失为菜单内有效候选的平均：

   ```text
   [(log π(j) − log π(0)) − (终局得分(j) − 终局得分(0))]²
   ```

   同菜单的 log 概率差等于网络原始评分差。保留历史与近期完整证据，不能只保存事后赢家。

5. **冻结候选，整局验收。** 配对种子、交换座位比较完整候选和参考；有希望的候选再用独立种子复核，复核数据不进入训练。
6. **通过才推进。** 更新完整已验收版本，处理依赖旧继续策略的过期标签。未晋级保留旧部署，不由训练中最新权重自动覆盖。

流程试图实现“发现有效接法 → 学会选择 → 整局兑现 → 保留”，实际仍卡在条件选择及泛化。局部对照之后由固定策略执行，完整候选却可能连续修改，所以整局验收仍必不可少。

入口：[event-train](../native/src/bin/event-train.rs)、[完整集合学习](../native/src/learning/event_sets.rs)、[event-agent](../native/src/bin/event-agent.rs)。

### 文件和指标怎样看

| 文件或指标 | 含义 |
|---|---|
| latest.json | 学习器、经验、优化器及部署等续训状态；不等于最强已验收策略。 |
| best.json / deployment | 已验收行为。没有晋级时不变是保护机制，不表示权重没更新。 |
| metrics.jsonl | 采集、拟合和候选覆盖；数据变化时，相邻 loss/现金不能直接比较策略强弱。 |
| evaluations.jsonl | 区分候选、参考、初筛、独立复核及晋级。 |
| comparisons.jsonl | 局部状态和真实终局分支；局部改善不是整局部署保证。 |
| 轮数、局数 | 每轮包含基础轨迹、剩余赛季分支和验收。不能统一按轮数乘 games-per-update 计算总成本；不同入口的 iterations 语义也应查对应版本。 |

小网络 GPU 更新短、CPU 分支模拟长，利用率低不能单独证明没有使用 GPU，也不能用跑满硬件代替有效学习。

## 5. 最后一次检查证明到哪里

固定第 10 轮，未新增对局、未修改生产模型。

| 检查 | 结果 |
|---|---|
| 完整菜单 | 320 份，80 个训练种子；66 份存在优于参考的选项。 |
| 非参考选项 | 1,532 个：119 改善、421 退步、992 持平。选项数与局面数不同。 |
| 数据和梯度 | 原始对照与缓存候选、标签一致，有效经验保留，梯度方向正确；Rust/PyTorch 概率复算最大差约 2.98e-8。 |
| 第 10 轮选择 | 320 份已见菜单中 317 次选参考，有效改选 0 次。 |
| 固定数据继续拟合 | 原 Adam 下再拟合 500 步，选中 3 个有效调整、另 4 个局面改差，平均记录得分增益 -0.003125。原生 Rust 复核同样没有净增益。 |
| 种子留出 | 初始模型另做固定预算拟合，60 个种子训练、20 个留出；留出 80 个局面中的 20 个机会选中 0 个，4 个局面改差。 |

留出检查仍来自历史自适应采集，不是新对局，也不是对 farm2945 的胜率。单独拟合一个有效局面可以成功，证明学习通路可用，不能证明混合数据上的条件化泛化。

**已确认：数据进入了学习，网络没有可靠区分何时值得改变。**

**尚未唯一确定：**状态是否缺少决定性信息、网络和优化能否表达条件差异、有限样本与终局标签噪声分别占多大影响。事后某方案获胜，不一定表示能根据当时可见信息预测它。

没有依据再把某个猜测包装成已确认修复，或承诺再训一晚就会成功。[最终审计](contextual_learning_final_audit.md)、[离线审计工具](../tools/audit_contextual_learning.py)。

## 6. 不应再次重复的错误

1. **现象不等于根因。** 等待、保守、不晋级、低利用率需要沿数据、梯度、选择和执行逐层查证，不能每次因此更换训练法。
2. **可执行不等于可学习。** 转产完成、回归测试通过，只证明执行能力，没有证明网络知道什么时候转产。
3. **局部拟合不等于策略进步。** loss、准确率、单点成功不能替代未见状态选择和完整比赛结果。
4. **采集、标签、部署范围不一致。** 比较两个动作却从几十个中部署，或局部学习直接接管开局，都使真实选择缺少对应证据。
5. **忽视继续策略和组合影响。** 标签依赖后续执行；刷新继续网络会使数据过期，单点有利也可能组合有害。
6. **经验保护与实际配额冲突。** 总容量淘汰长期优秀样本；按赢家分类偏置正负样本。必须检查实际留下了什么。
7. **交易脱离生产需求。** 高频买卖吞噬预算，采购、库存与销售应服务于具体计划和资金义务。
8. **把停滞都归因于对手。** 对手提供挑战，不能替学习器掌握条件差异。
9. **现金或产量替代胜负。** 双方影响价格；大胜变小胜不应自动抵消输变赢。最终目标保持终局比赛得分。
10. **固定小面板上涨就宣告成功。** 反复选择有偏差，独立复核也有统计假设和多次比较限制，不保证真正单调变强。
11. **短测为长训背书。** 连通性和执行回归不能证明经济收益。我们多次过早从修复结构问题跳到建议整晚训练。
12. **只修局部，忽略整体闭环。** 新模块必须讲清谁采样、比较谁、标签依赖谁、最终执行什么、怎样保留。增加动作、字段和版本不能代替这条链。

协作上的教训也需要留下：助手多次把正确的局部分析说得过于接近一个足以改善训练的方案，让用户承担了额外服务器、时间和实验成本。结果不佳不能简单归结为用户训练不够久。

## 7. 收尾与交接

值得保留的资产包括 Rust 模拟与执行链路、批次和资源账本、混合路线、版本化检查点、终局对照、配对验收，以及可复查的失败证据。它们是工程基础，不等同于已获得有竞争力的学习策略。

建议归档：

- 本文、各阶段复盘、最终审计文档与工具。
- 关键实验的 manifest、运行命令、metrics、evaluations、comparisons 和日志。
- 对应版本的 initial、best、latest 和审计用固定检查点；保留来源和合同版本，不混用旧经验与新执行语义。
- 支持关键结论的回放和离线审计输出。

**.gitignore 忽略 runs/、replay/、*.pt 和编译产物。提交源码与文档不会备份模型、日志和回放。** 如果释放服务器，应另外保存需要的实验文件；本次整理没有执行外部备份、Git 提交或推送。
