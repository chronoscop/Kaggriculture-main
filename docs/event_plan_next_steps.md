# 下一步：在真实经营事件上选择和修订可执行计划

状态：本文件保留最初设计；首个可运行范围已实现，实际接口、边界和命令见 [事件计划训练](event_plan_training.md)。保留现有 plan-improvement-v3 检查点。

## 已确认的教训

- v7/PFSP/经验保持解决了部分挑战和保留问题，但不能补候选中没有的能力。当前不同时重写对手调度。
- v8-market-3 曾开放交易量、顺序、公开对手供给、事件触发。交易样本占 77.6%，自己的订单可能再次触发交易；采购与生产需求脱节。新增市场动作或仅仅改成事件触发，不构成新的解决方案。
- plan_rl_trial 的现存24轮权重均更新、没有被回退；固定确定性评估在0/10/20轮相同。不能把“参数动了”当作能力改善，也不能无证据断言是KL太强。
- plan_compare_trial 在少量非开局状态学习后直接接管全局，第二轮16局全部无生产；局部排序学习和全局接管不匹配。
- plan_improvement_trial 保留了3次验收改进，但第55轮后没有新晋级；小样本、未实测的greedy选择、一次窗口接管都限制改进。失败原因不能全部归为门槛严格。

证据：`competition_replay_review.md`、`plan_compare_trial_review.md` 和上述运行目录。当前计划底座固定监控已有开局21格、峰值约63格、15工人和大量混合路线；不要再把旧mixed的每天2项目当作当前原因。

## 当前具体缺口

1. `plan_chain::Link` 表达first/next/cycles，active承诺受保护但缺少有条件修改尚未执行阶段的接口；`supplies`使用固定备料时机。
2. `Executor::reserved`覆盖当前路线的地格、种子和取货；`plan_prototype`主要用plots_per_worker估算承载能力。已有现金/物料防重占机制，但缺统一的多计划未来服务窗口与条件性资金安排。
3. `plan_chain::sample`沿用通用观测；候选32维聚合第一/后继种类、数量、耗时等，active义务只粗略表示。需要明确编码每个活动计划的阶段、下一项支出/交付、截止时间和资源缺口。
4. 时间窗口的首个机会不是收获、到货、资金充足、服务延期等经营事件。不能直接改成每次事件都让未经验证的新模型接管。

这些是可证实的结构缺口，不等于已证明它们解释全部平台期。

## 一个完整实现单元

先实现“已在生产的一批地块，下一轮继续种/部分转产/延后”的可修订计划。品种和规模从合法集合生成，不把DECEM某局的作物配方写成答案；继续当前安排始终是候选。

### 数据结构（拟新增）

```rust
struct BusinessPlan {
    id: PlanId,
    revision: u64,
    sites: Vec<Pos>,
    stages: Vec<Stage>,
    cursor: usize,
    reservations: ReservationId,
    status: PlanStatus,
}
struct Stage {
    guard: Guard,               // 真实收获/到货/现金和资源条件
    production: ProductionBatch,
    materials: MaterialTarget,
    funding: FundingPolicy,    // 运营现金保留、筹资销售目标、采购支出上限
    service: Vec<ServiceWindow>,
    deadline: i64,
}
enum PlanEdit {
    Continue,
    Start(BusinessPlan),
    RevisePending { id: PlanId, from_stage: usize, replacement: Vec<Stage> },
    CancelPending { id: PlanId, from_stage: usize },
}
```

这是一组候选的语义结构，不是固定动作序列。网络选具体候选，数量、种类、备料时机及资金保留要求均作为候选差异。执行器将它落实为真实命令；不能仅添加结构字段而继续忽略它们执行。

### 模块职责

- 新增 `plan_events.rs`：根据真实回执、批次阶段和阈值跨越发出事件，带plan_id/phase/version用于去重。同一批次同回合合并事件。物料到账可推进阶段；自己的交易波动不自动成为新的投机机会。
- 新增 `plan_resources.rs`：统一账本，区分现货、已预留、已下单未到账；当前支出只能用已到账现金，未来销售仅形成条件。先扣已承诺近期待办和运营支出，再给扩张分配余额。现金、仓储和订单数硬约束；工时使用含行走、取货、返仓的服务窗口估计，结合既有路线剩余占用，延期时释放/修订未执行阶段。不能把启发式工时估计称为保证可行。
- 扩展 `plan_chain.rs`：候选由同一事件、同一可修改地块集合构造，包含继续/缩小/换种类/不同备料时机等少量有意义变体。执行前联合验算并原子预约；尚未落实的采购不能当库存。仅修订尚未执行的阶段；对已有生产的退出作为显式候选并计实际成本。
- 扩展 `plan_prototype.rs`/`executor.rs`：基础补货、雇工、扩张和销售统一经过账本，防止计划预留与原规则争抢同一资金/材料。保留经济路线和回执执行；把计划服务窗口与材料依赖送入路线生成，而非停留在features里。多个计划可共享一条可行路线。
- 新增计划编码：活动计划集合 + 资源缺口/服务压力 + 候选各阶段商品、数量、时点、净投入及预计产出。预计值是输入，实际分支终局结果才是收益监督。
- 修改 `plan_portfolio.rs`/`plan-train.rs`：使用同一事件键及执行器。先验收一个批次的整段接法；重复接管更多批次属于范围扩大，必须评估整套候选后才部署，不因事件数量增加直接放开全局。

### 具体运行例子

四格小麦接近收获，比较：继续四格小麦；两格继续回款、另两格转畜牧；先继续一轮再转。

每个候选明确下一阶段耗料、实际可支付预算、饲料/雇工预留、服务时间窗，以及何时卖出未预留库存以筹集资金。若尚未到账，则保留现有生产并等条件满足。若市场/服务条件使原计划不合适，只修改未执行部分；不抹掉已花掉的成本、不无偿移走现有动物。

不为每笔买卖新增策略样本；交易是所选经营计划的执行结果。此阶段的灵活性来自多种带资金约束的计划选择，不声称已实现自由交易策略。

## 与现有学习机制连接

同一状态克隆：A=当前已验收安排；B=网络当前准备改用的安排；C=一个不同经营方向的可行安排，重复项去重。分别执行计划并用冻结的同一后续策略继续到终局，对手随分支状态正常反应。比较整局胜负与相对现金差；不把全场销售收入伪归因给单个项目。

网络用实测A/B/C的收益差学习；没有执行过的候选不贴标签。优先补网络当前greedy改变却缺少证据的训练局面，保留全局探索预算。新旧样本须标明后续策略、候选/执行契约版本；改变条件后的旧收益标签不直接复用。

仍用独立种子完整对局初筛/复核保留冻结行为。验证局不进入训练。旧检查点保留独立运行作为基准；新增输入/事件契约需要显式版本化，不能把旧权重静默解释为新能力。

## 实施顺序与完成标准

1. 把一个批次计划的事件、统一资源账本、继续/修订、回执执行和网络编码做成一条完整路径。只完成生成候选或新数据结构，不算完成。
2. 接入A/B/C真实分支学习，保留已验收策略与整局验收。范围有限、训练与部署一致；后续按验收扩展到多个批次。
3. 做针对性检查：同时两个计划不会重复占钱/物料；资金不足保持现有生产；收获后用已备物料衔接；采购失败不虚构库存；市场/服务变化只调整未执行阶段；采集和部署事件消费一致；坏候选不覆盖已验收行为。只验证实现，不拿smoke当经济提升证据。
4. 给用户实验命令。判断改进要看真实终局结果和计划兑现，不能以交易次数、混合比例、链条数量或loss代替。

不同时改奖励、对手、优化器和经营接口；不重启参数搜索，不把所有已有权重作废后再次无条件要求从零长训。框架延续，执行与编码变化必须如实说明兼容边界。
