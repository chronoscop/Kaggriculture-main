# mixed-production-v5

## 运行结构

`Observation → 项目/回执更新 → 投入候选 → 空闲工人路线候选 → GPU 选择 → Rust 动作执行 → 环境结算`

- `native/src/pipeline/executor.rs`：生产项目、独立可见观测、资源预留、跨回合路线和实际回执。
- `planner.rs`：采购/雇工/开地/转产候选，混合路线插入与本地物理模拟。
- `encoding.rs`：96 维场景和 32 维候选特征，含路线步数、任务种类、肥料复用、续种、成本、位置和附近生产。
- `rollout.rs`：CPU 多局并行推进，集中 GPU 批量推理，实际终局回报。
- `native/src/learning`：候选评分网络、PPO、Adam、检查点。
- `mixed-train`：训练、恢复、轻量对手评估；`mixed-agent`：持久 JSONL 原生代理，仅用于外部评估。
- `src/route_rl/evaluate.py`：原版 farm2945 对战评估客户端；没有 Python 采集或训练入口。

## 规划规则

生产项目记录地格希望维持/切换的用途，工人路线不永久绑定项目。
每条候选从该工人的实际位置和背包出发，连接多个地格任务并计算返回卸货。
采集肥料会增加背包库存，后面的 FERTILIZE 必须实际具备肥料；种子从共享库存扣除。
买入只发出订单，后续路线必须等待真实库存；不能用预计采购当作已经到货。
失败的未确认项目会超时释放。已经确认的项目可在收获后继续生成生产任务。

当前有界搜索：每个服务分支考虑最近 8 个地格、保留 3 个部分方案、最多连接 4 个地格；
使用养护/提前收获/简化服务三种分支，保留可执行的不同路线交给 RL。
规则按任务完成、物料复用和步行成本限制搜索宽度，没有穷举所有排列。
这存在搜索偏好，不能称为全局最优路线。

其他工人的路线预留地格、种子与出仓物料；新候选不重复占用。
早先批准的新项目优先保留种子，缺种时不能先清掉既有作物再假设采购成功。
执行器按实际工人顺序再检查一次动作；发生缺货或路线错位时使受影响路线失效。
DROP 前重查容量，避免游戏规则把溢出背包货物丢弃。
路线限于当天实际剩余回合，夜间清除工人路线；项目跨天保留并重新安排服务。
策略接收自身 private、双方公开农场和市场，无法读取对手背包、种子、完整环境 seed。

## 决策范围和限制

RL 可选择候选中的新作物/动物、地格、后继用途、退出、采购、雇工、开地和工人路线。
初版每次新增项目考虑 3 个近仓地格及各品种，路线候选最多约 40 个，投入候选最多 96 个。
日后要扩大位置和路线搜索，需要与吞吐、经济结果一起验证。

- 现有未失效路线持续执行，暂未提供任意中途抢占和跨工人交接物料。
- 后续工时检查使用项目负载的保守近似，不是整个赛季的精确联合排程。
- 新动物、种子、工人均按实际资源和剩余赛季筛选；当前采购不预支同回合预期销售回款。
- 投入重评通常间隔 6 回合；换日或显著现金到账可提前触发。
- 退出动物项目停止追加喂养，待动物离开后再清理；没有伪造出售/移除动物的动作。
- 初版销售为规则结算：先销售可用产品，保留一定饲料/肥料，再提交选择的采购。
- 小型网络可能无法持续占满 A40；增大同时采集对局数提升有效批量，不靠重复计算制造利用率。

## 学习和检查点

策略为可变候选集的 masked softmax，不再使用 baseline KEEP/CHANGE 门控。
每次采集固定一份模型，完成整局后才更新。默认对轻量 Rust 规则对手训练；可选 selfplay。
自对弈仍按同种子双座位各跑一局；两席样本都进入训练，采样随机流不同。
奖励为 `(终局己方现金 - 终局对手现金) / 10000`，分配给该席事件决策作为 Monte Carlo 回报。
不额外奖励步行少、任务多或混合程度，以上只作诊断指标。
PPO 保留 0.1 clip、0.02 KL 停止、0.5 梯度裁剪；不对小批次强行减去优势均值。

检查点 schema 为 `mixed-production-v5-ppo-v1`，特征契约为 `mixed-routes-96x32-v1`。
保存模型、Adam 动量/步数、学习率、迭代数和 SplitMix64 状态。中途退出只从已完成迭代恢复。
此版与旧 v4 及旧 farm2945-native checkpoint 不兼容。

## 指标怎么读

| 指标 | 含义 |
|---|---|
| samples / updates | 真实策略决策数 / 实际 PPO 小批次更新数 |
| rollout_seconds | 整局采集耗时，包含规划、环境与推理 |
| inference_seconds / mean_inference_batch | 推理累计耗时 / 平均同时决策数量 |
| update_seconds | 参数更新耗时 |
| cash | 两席实际终局现金，按 learner_seat 找学习方 |
| mixed_routes | 选中的同时含种植业和畜牧业任务的路线数 |
| material_routes | 选中的含沿途收肥→施肥的路线数 |
| harvested_units / fertilizer_used | 执行器实际投影确认的收获数量 / 施肥次数 |
| invalidated / receipt_failures | 动作失效或错位 / 与下一次真实观测不符 |
| expired_projects | 未确认且缺货的超时项目 |

`mixed_routes` 和 `material_routes` 是计划选择统计，需结合实际收获/施肥和回执看，不能直接等同利润。
`--trace 1` 输出逐回合动作和被选计划，适合小规模排查；长训练建议关闭。

## 已有验证

- 实际环境中的牛服务→收肥→草莓施肥→收麦→续种浇水→返仓销售。
- 双工人资源与地格互斥、失败采购、仓库满时保货、错位重规划。
- 改变对手私有信息和环境种子，不改变给定可见观测下的候选/特征。
- CPU/GPU 前向、更新、断点恢复与旧版本拒绝。
- 完整对局采集和 CUDA 更新冒烟；经济效果仍需独立评估。
