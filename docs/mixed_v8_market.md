# 可学习市场决策（v8-market-3）

## 目标与范围

模型联合选择生产投入、工人路线、销售时机与数量、小麦/肥料采购量；按完整赛季的真实现金结果学习。独立 actor/critic、PFSP、近期对手快照和原有成功经验辅助学习继续使用。这个版本没有宣称已经解决长期遗忘，先让买卖成为真正可选择的动作。

## 实现

- `--market-mode learned`（默认）：每次从所有合法的“商品＋买卖方向＋数量”中选择下一笔交易，也可以选择结束本轮交易、暂存剩余产品。每笔之后重新生成候选，销售能释放现金和仓位，较早的采购会占用后续预算。交易优先顺序由策略决定。
- 数量候选：1 单位和可执行上限的约 10% / 25% / 50% / 75% / 100%（向上取整、去重）。销售上限为扣除已承诺取货后的仓库数量；采购上限按整条价格曲线、预留后的现金和仓位计算，不再固定最多 16 单位。另提供补足已知物料缺口的采购量，以及单个商品足以覆盖周转资金缺口时的最小销售量；这些都是可选项。
- `--market-mode rule`：保留原先自动销售、固定饲料留存与缺粮采购，作为同版本对照。两组均使用新增市场观测和独立网络，因此对照比较的是交易决策能力，不是复现旧 v7 模型。
- 每 4 步提供兜底机会，另在可交易商品报价变化达到约 3%（至少 1 元）或市场库存变化至少 4 单位、返仓/到货、实际现金增加或支出变化至少 50 元、资金能否覆盖经营需求发生变化、物料短缺加剧、仓库首次达到 90 单位、选中投资订单时提供机会。变化相对上次交易阶段开始时已观察到的状态计算，不读取未来结算。最后一天（step 696–718）逐回合提供机会。市场暂存不停止生产，也不强制下单。
- 先选择项目/路线，再计算本方单位动作的结果，交易决策能看到当回合实际可返仓的产品。模型可以先售出产品，再用回款在同一批订单中补饲料，也可以先采购或只进行部分交易。其他投资候选仍按已到账现金生成，新增销售到账后可触发下一步投资决策。
- 每商品每阶段最多一笔交易，防止同阶段反复买卖；阶段间仍可再次交易。候选列表顺序不限制实际交易顺序。不学习挂单价格；游戏接口提供的是市场成交订单。价格和整笔金额按公开库存逐单位计算，买入取扣库存后报价，卖出取增加库存前报价，遵守 1 元价格地板。
- 为已选中的种子/动物/雇工/开地订单保留现金和动物仓位，为尚未执行的路线取货保留物料。所有订单共享一个现金、仓库和 10 单上限的账本，不在末尾静默截断模型交易。
- 账本报价假设没有对方同步订单，只是决策用估计，不保证成交价或全部成交。真正奖励、日志金额来自引擎实际结算，不把预计卖货收入记为已实现现金。

## 输入和训练

- 观测 320 维，候选仍 32 维，类别从 16 扩至 19（16 结束本轮交易、17 卖出、18 买入）。
- 新增商品相对基准价格、库存偏离、4/24 步价格与库存变化、已开店铺消耗速率、自己携带/已承诺物料、仓库余量、种子/饲料现金需求、未结算交易金额、双方公开生产布局和当前可收获量。新增剩余可选商品、订单余量、触发原因、数量占合法上限比例及交易后的资金缺口，帮助策略理解交易阶段的状态。
- 历史只来自该座位实际观察；对手仓库、种子和工人背包不会作为输入。没有未来价格标签或实际未来状态输入。
- 交易决策进入真实采样概率的 PPO。暂存也是可探索动作。现金回报仍是实际 cash delta，gamma=1，按时间间隔的 GAE；库存按当前标价涨价不会产生奖励，终局剩余库存不当现金。
- 每局成功经验最多 32 行，生产和交易各保护最多 16 行，某一类不足时另一类填充。允许已实现盈利且有卖出决策的纯交易局进入经验筛选；普通亏损局不会作为成功经验。
- 评估中的 inactive 判定允许有实际买入、卖出且终局现金高于初始值的交易局。胜负和晋级仍看真实现金及对战结果。

## 对手潜在供给信息（market-3 新增）

`public_supply.rs` 每回合只读取对手公开地格，维护最近 24 步的观察历史，供生产与交易决策共同使用：

- 每种作物：未成熟地格数量、最早一批距离首次成熟的步数，以及未来 24 / 72 步内达到首次成熟的地格数量。成熟时点按 `(种植日 + 首次成熟日龄) × 24` 计算，保留当前小时；超过最后可执行 step 718 的批次不算作赛季内即将成熟。
- 五类作物、三类动物：过去 4 / 24 步的地格数量变化和公开可见产量变化。
- 最近 24 步观察到的新增/移除数量：按地格、品种、种植/放置日识别批次变化，因此同一地格更换一批、总数量不变时也可保留信号。开始观察前的生产不算新增，公开状态无法区分的同日同种替换也不虚构出来。
- 提供实际观察历史长度，开局不足 24 步时使用已有历史，不补造过去的数据。

这些是潜在供给线索。成熟还取决于后续养护和存活，产量下降也可能来自收获、清除或损失，不能直接当作销售。对手仓库、携带物品、购买意图和未来动作都不作为输入。首次成熟后的连续产出作物由当前可见产量及变化描述，本版不预报后续产出或出售时点。

新增 `trade_events.rival_supply`：相对上次交易机会，对手种养数量、公开产量、成熟可收获量、观察到的批次更换、临近成熟的地格数量发生变化时，提供一次新的交易机会。只减少一步的成熟倒计时不触发；模型仍可选择暂存。交易合法性、现金奖励和结算继续由既有流程处理。

`rule` 和 `learned` 都获得相同的新公开观测；`rule` 的交易仍按固定规则执行。本次两组比较检验整个学习交易方案，不能单独证明供给特征的增益；若要单独归因，后续需要同版本特征消融。

## 用户运行的对照实验

建议先各 100 轮、各 3200 局，串行执行避免抢 GPU。这是判断学习趋势的试验，不足以确定最终能力上限。两组交易决策数不同，PPO 样本数、梯度更新次数与耗时也不同：这里控制对局预算，不声称是相同算力预算；比较时同时记录这些开销。相同 seed、轮数和对手调度规则；两组策略不同后，对手池自然会演化成不同模型，训练原始胜率不能当成严格配对测试。

```bash
for mode in rule learned; do
  run_dir="runs/mixed_v8_market3_${mode}_trial"
  mkdir -p "$run_dir"
  native/target/release/mixed-train \
    --out "$run_dir" \
    --iterations 100 \
    --games-per-update 32 \
    --workers 7 \
    --device cuda \
    --epochs 2 \
    --batch-size 256 \
    --seed 1200 \
    --opponent league \
    --market-mode "$mode" \
    --eval-every 5 \
    --eval-games 8 \
    --eval-seed 1000000000 \
    --exploration 0.2 \
    --imitation-weight 0.05 \
    > "$run_dir/train.log" 2>&1 || break
done
```

共 6400 局采集，另加评估。screen 中可直接执行。不要复用含旧 metrics 的目录；失败时日志中有原因。

### 两组模型直接对战

```bash
native/target/release/mixed-train \
  --mode evaluate \
  --resume runs/mixed_v8_market3_learned_trial/latest.json \
  --opponent-checkpoint runs/mixed_v8_market3_rule_trial/latest.json \
  --out runs/mixed_v8_market3_learned_vs_rule \
  --seed 4501000000 \
  --games-per-update 32 \
  --workers 7 \
  --device cuda
```

32 局为 16 个种子交换座位；程序校验种子与双方训练/晋级种子都不重叠。外部对手只用于评估，不改模型、对手池或成功经验。`--opponent-checkpoint` 不与 `--opponent` 同用。

## 看什么结果

- `evaluations.jsonl`：确定性终局现金、对冠军表现和晋级；共同对手和直接对战是两组比较依据。
- `metrics.jsonl.trade_samples`：实际进入 PPO 的交易决策数量。
- `games[].stats[seat]`：trade_sessions 是触发的交易阶段数；trade_events 分别记录 9 种触发原因，原因可重叠，不能求和当阶段数。trade_decisions、trade_holds、sell_orders、buy_orders 是选择次数，不是成交数量；trade_holds 在本版表示结束本阶段的次数。
- `games[].stats[seat].trade_events.rival_supply`：因对手生产信息变化获得交易机会的次数，不能当成获利次数。
- `games[].learner_seat` 指出本局模型所在座位；cash 和 trading 数组按座位排列，不总是左侧为自己。
- `games[].trading[seat]`：sales_revenue、total_spending、ending_stock；products 下每商品记录实际 sold_units、sales_revenue、bought_units、purchase_cost 和仓库期末量。平均成交价可由金额/实际数量计算，数量为 0 时不计算。
- 程序内部维护的每单位实际结算价格已经包含对方同步订单影响。总支出还包含种子、动物、雇工和开地；不要把交易流水当利润，也不要将不同产品直接平均成一个售价。
- 同时检查生产完成、资金周转和期末积压：模型不能只靠囤货估值让指标好看。工人尚未运回仓库的物料也不能当最终现金。

两组训练后，用同一批未参与训练/晋级的种子评估，并交换座位直接对战。优先看确定性终局现金、对战收益差、生产是否维持、期末库存和买卖成本；交易次数或流水增加本身不算提升。若 100 轮仍亏损或保守，先分清生产退化、交易亏损、库存积压及随机/确定性表现差异，再决定是否加轮数。

这里只进行功能与短验证，100 轮比较和长训练由用户运行。是否提高利润取决于实验结果。
