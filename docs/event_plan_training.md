# 事件与下一批生产对照学习（v4）

入口为 `event-train` / `event-agent`。这是已实现的首个范围：现有作物临近收获时，选择下一批的品种、1/2/4格数量、是否多生产一轮、备料时机和运营现金保留；在到货、可负担条件变化、延期或后继产品报价明显变化时，修订尚未投入的部分。

不是任意长度计划生成器，也没有重新开放逐笔自由买卖。已放养动物的主动退出不在本次新增修订范围内。

## 继承什么

可以用 `--base-checkpoint runs/plan_improvement_trial/best.json` 加载第55轮、3次已验收改进的完整经营策略。其旧网络及原输入语义冻结保存，新事件网络从零初始化。未有事件策略晋级时，逐步行动仍使用该底座。

`--base-checkpoint` 不是续训旧网络；不会复制旧Adam或把旧320维权重解释为新的计划输入。v4检查点内同时保存冻结底座、已验收事件模型、训练中事件模型、Adam、随机状态和同版本经验。恢复当前事件契约的v4才使用 `--resume`；两参数不能同时指定。最终审查后的事件契约为 `event-batch-context320-actions32-v2`，此前事件v1检查点不能直接续训；旧v3已验收底座仍可通过 `--base-checkpoint` 导入。旧文件和旧入口保留用于对照。

## 实际运行路径

1. `plan_events.rs` 纳入冻结底座的旧待执行链接和新批次，以地块/种植代次及链接/批次修订号校验身份。部分修订不会让剩余地格重复报告同一代收获；失效的排队事件不能操作替换后的安排。采购真实到账、到了采购窗口且扣除其他优先承诺后跨过可负担门槛才产生相应事件；报价变化需超过阈值，延期使用创建承诺时锚定的服务期限。
2. `plan_chain.rs::revise_batch` 仅修改可编辑、尚未投产且没有在途路线占用的地格。部分调整保留其他地格；取消不会抹掉库存或花掉的钱。修订废弃的旧链接记为 `superseded`，与真实执行失败区分。
3. `plan_resources.rs` 汇总现金、材料及工作需求。材料按实际地块与品种合并当前路线和待投产项目的预约，同一地块不重复计数、不同地块分别占用；已下单不会立刻变成库存。**先支付当前生产必要养护/续种，再用实际剩余现金给后继备料，最后限制可选扩张。** 未来销售收入不能提前支出。
4. 批次的备料时机决定采购何时出现；资金不够就继续当前生产并等待。选择再生产一轮时，首次收获后的空地仍续种当前品种，不能提前转产。规则交易出售未保留产品回款，已有动物饲料受保护；采购/销售没有各自产生大量训练样本。
5. 新计划的服务窗口进入路线目标预筛和评分，原有取货、种养服务、收肥施肥、收获续种可以继续共享路线。工时包含近期在途路线、行走和服务估计，不是精确的全季调度保证。
6. 计划结束后释放新层的资源/调度保护，回到原经营规则；不因为做过一次新计划永久改变其余经营。

## 模型能看到什么

新320维上下文明确包含实际现金、运营保留、后继缺料金额、可用工时、仓储、商品报价/市场库存/自有库存、双方公开种养数量、每个地格的已承诺后继品种和预计接续时间、各品种的阶段与缺料统计、当前批次的备料时机及截止时间。候选32维表示具体品种、数量、成本、周转时间、备料提前量、保留现金和新增工作压力。

只使用公共信息与自己的观测。计划工时/产出预测用于候选和输入，收益标签来自真实终局结果。

## 学习与接管范围

- 同一状态保留A：已验收选择；优先续演B：网络当前不同的首选；另续演C：不同生产方向的探索。若网络仍选A，就测两条探索备选。去重后最多两条替代分支。
- 每条分支只替换当前事件选择，后续使用同一已验收策略，执行至step719，对手正常响应分支中的市场变化。实际A/B、A/C收益差共同训练同一个评分网络；仍使用原来的胜平负优先、相对现金差辅助目标。
- 每局从实际出现的可选择事件中取最多 `branch-points` 个对照点；硬保留一个轮换覆盖点，覆盖全部16种事件机会。剩余预算交替优先网络分歧和资源事件，轮换资源种类及序号；目标未出现时用实际事件补位，避免Material低序号长期占满预算。
- 首版受限为四种事件各前四次**存在不同合法候选**的机会，共最多16次。新的冻结模型按事件种类/序号接管一次；没有模型的机会继续底座。不是每次事件都无限制调用未验收网络。
- 单次晋级替换其中一个事件机会的模型。采集、分支、整局验收和部署共用事件消费状态。通过独立初筛和复核才合入；失败不改底座或当前已验收事件组合。
- 标签绑定当前后续策略版本。晋级清除当前训练bank，历史证据仍留在JSONL，已验收能力由冻结模型保留。验收数据不回流训练。

## 实验命令

本机二进制已构建。必要时重新构建：

```bash
export PATH="/tmp/route-rl-rustup/toolchains/stable-x86_64-unknown-linux-gnu/bin:$PATH"
export CARGO_HOME=/tmp/route-rl-cargo
cargo build --manifest-path native/Cargo.toml --release --features train --offline --bin event-train --bin event-agent -j 4
```

在screen里执行，使用新目录：

```bash
mkdir -p runs/event_plan_trial
native/target/release/event-train \
  --out runs/event_plan_trial \
  --base-checkpoint runs/plan_improvement_trial/best.json \
  --iterations 100 --games-per-update 16 \
  --branch-points 2 --alternatives 2 \
  --workers 7 --device cuda \
  --epochs 8 --batch-size 64 --learning-rate 0.0003 \
  --eval-every 5 --eval-games 8 --confirm-games 16 \
  --seed 2400 --eval-seed 1200000000 \
  > runs/event_plan_trial/train.log 2>&1
```

100轮最多1600局基础对局、6400条剩余赛季分支，另加验收；实际分支数由可用事件决定。每次 `iterations` 都是额外轮数。续训用新输出目录和 `--resume runs/event_plan_trial/latest.json`，去掉 `--base-checkpoint`。

新种子与此前100轮采集/晋级使用的区间分开。本次固定监控种子也换了，因此不能直接用新现金与上一版固定8局现金做强弱结论；主要看本次同种子配对的candidate/incumbent及初始底座。

## 输出

- `metrics.jsonl`：对照数、事件覆盖、实测更好备选、收益差学习误差、采集/更新时间。
- `comparisons.jsonl`：事件身份、具体下一批安排、实际终局现金及后继执行结果。
- `evaluations.jsonl`：初筛/复核、`promoted`、事件层`accepted_revision_after`；初始事件revision=0仍可能包含旧底座的3处改进。
- `games_detail[].batch_plans`：实际批次、备料提前量、现金保留、取消/修订、投产及产出回执。
- `latest.json`：完整续训状态；`best.json`：最近通过验收的组合。`event-agent`只读取部署组合，不读取训练中权重。

单元测试和CUDA短运行验证执行链路，不证明已超过旧冠军或能长期持续提升。正式经济效果由这次用户运行的实验判断。
