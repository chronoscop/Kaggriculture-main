# 事件计划训练：分季节机会与同批次两次决策

入口：`event-train` / `event-agent`。当前外层检查点仍为 `event-plan-improvement-v4`，输入/执行契约更新为 `event-batch-context320-actions32-season-pair-v4`。

## 这次解决什么

旧事件实验到第45轮没有晋级。2558条分支只有6条位于step360以后；四类事件的前四次机会大多在前半季耗尽。分支只试一次修改，更新后网络真正首选也经常没有直接对照。这些是代码和日志已确认的缺口，不代表已经证明了停滞的全部原因。

本次继续沿用批量生产、混合经济路线、两阶段转产、共享现金/物料/工时约束以及冻结底座。目标是让模型在生产过程中选择下一批安排，并在后来的真实情况变化时修改尚未执行的部分。DECEM回放支持这种经营行为；这里没有声称复现其未知训练算法。

历史边界：不恢复v8的高频独立交易；不重复plan_compare的未经验收整局接管；不把参数更新、路线变多或现金变多当成胜率提升。

## 完整执行与学习循环

1. **机会覆盖四段赛季。** 收获、到货、可负担、经营复核四类事件，各自在0–179、180–359、360–539、540–719中最多领取一个合法机会，共16个范围。时间段只分配机会；必须有真实事件和合法候选才能决策。季末仍受真实生产完成时间限制，不强行安排无效生产。
2. **每个范围可接管两次有联系的选择。** 第一次选择下一批品种、1/2/4格规模、继续生产几轮、备料时机和现金保留。如果创建了新批次，只为这个批次登记一次后续修订机会。它必须来自之后的新事件，批次身份及修订号仍有效；最多再决策一次，不递归扩张接管。取消或不改计划不会创建后续接管。
3. **保持资源与执行一致。** 日初雇工刚到期时，先执行原经营维护，再用下一次真实观察判断可用工时；不提前把采购或雇工当成到账。后续事件暂时被路线占用时保留排队资格，不被普通事件配额删除。 当前作物、动物、在途工作和已付款材料保留真实状态。只能修改可编辑的未执行安排；未来销售款不能提前花。材料预约、实际采购、混合路线、季末检查仍走同一套执行器。
4. **真实执行对照。** 在已验收轨迹的同一状态克隆分支，先执行第一次修改；如出现同批次后续事件，再比较保留该安排与修订安排，均走到step719。采集还探索一个不同的后续修订，用于训练后续选择。未出现后续机会时如实记录，不伪造事件。
5. **比较主选择时继续策略一致。** 如原已验收首选本身也会创建批次，额外实测它搭配本次冻结后续网络的结果，再与其他主选择排序。原已验收完整策略的结果另留给整个方案的胜负比较。避免把更换后续网络的效果错误归因给主选择。
6. **两个模型一起冻结并验收。** 主网络持续学习；后续网络在一段更新期间冻结，主选择标签注明这个继续策略版本。后续决策输入的`context[295]=1`，主决策为0；条件分支带`prefix_id`，不会混成已验收轨迹中的状态。
7. **更新后补测实际首选。** 每次验收前冻结当前主网络和后续网络，用新训练种子实际执行当前首选的完整两次决策组合。用这些实测结果挑选值得完整验收的范围；补测和验收之间没有梯度更新。补测训练证据可进入下一次更新，独立验收种子绝不进入训练。
8. **小步替换一个完整范围。** 候选一次只替换一个范围的主模型及后续模型。其他已验收范围和底座不变。独立完整对局未通过，就保留部署策略。通过后，两部分一起部署，采集与`event-agent`共用同一`prepare/execute_choice`。

每次验收后，先让下一次更新学习刚补测的数据，再刷新冻结后续模型。更换后续模型后，旧主选择的条件标签退出活动经验库；后续状态自己的对照仍以已验收策略继续执行，可保留。完整已验收策略变化时清空当前活动bank，历史证据仍保存在JSONL，能力由冻结部署模型保留。

这仍是有界的两次决策，不是任意长度计划或自由交易系统。工时预估不是精确全季调度保证。

## 目标与晋级

唯一优化目标：720回合终局胜1、平0.5、负0。绝对现金、现金差、产量只作诊断。同胜或同败但现金不同，标签仍为0。

初筛比较同种子、座位、对手下的完整候选与已验收策略；得分改善才进入另一批独立种子复核。不设最低改善幅度，不按现金差或改善种子数量一票否决。

复核按独立种子聚合同种子的两个座位及对手，再做单侧配对符号翻转检验。证据不足且均值为正时，累计追加到`confirm-games`的2倍、最多4倍；最多三次查看，每次使用单候选0.05/3的检验预算。仍不确定就记为`inconclusive`并保留旧策略。这里有零假设下配对差值对称的统计假设，且只控制单个候选的三次复核，不保证整晚所有晋级均无误差，也不保证训练单调提升。

## 夜间命令

在项目根目录的screen中运行，使用新目录。`iterations`是额外更新次数，不是总轮数；每轮16局基础轨迹及若干剩余赛季分支，每5轮另有冻结首选补测和可能的独立验收。

```bash
mkdir -p runs/event_plan_pair_overnight
native/target/release/event-train \
  --out runs/event_plan_pair_overnight \
  --resume runs/event_plan_trial/latest.json \
  --iterations 400 --games-per-update 16 \
  --branch-points 2 --alternatives 2 \
  --workers 7 --device cuda \
  --epochs 8 --batch-size 64 --learning-rate 0.0003 \
  --eval-every 5 --eval-games 8 --confirm-games 16 \
  > runs/event_plan_pair_overnight/train.log 2>&1
```

400轮包括6400局基础采集；若从第45轮恢复，还包括80批、共1280局冻结首选补测基础轨迹，另外有分支和独立验收。实际耗时取决于后续事件数量及复核是否扩样，不能按旧版本的每轮耗时保证固定10小时。想提前结束时可以Ctrl-C，下次从最近完整的`latest.json`在新目录恢复。

## 输出如何看

- `metrics.jsonl`：已验收基础轨迹的得分、现金；主/后续对照学习误差；覆盖与模拟成本。基础轨迹现金不是学习中网络逐轮成绩。
- `comparisons.jsonl`：`stage=primary/followup`、`prefix_id`、`frozen_followup_version`、真实现金、事件身份与执行回执。`reference_cash`与`alternative_cash`是同一继续策略下用于学习的对照；主记录的`incumbent_cash`与`package_score_gain`才是完整新组合相对旧部署的成绩。`auxiliary_reference=true`是补测共同继续策略的参考，不重复算作首选支持。
- `keep_at_followup_cash`：第一次修改后，在保留的后续事件选择Keep的终局，不是完全禁用后续事件接管的另一种策略。
- `evaluations.jsonl`：`support.source=frozen_post_update_actual_package_rollouts`说明支持来自冻结候选首选实测；`support.slots`只覆盖本次抽到的局面，未测候选不自动视为可靠。`screen`、`confirmation_looks`与`confirmation.evidence.decision`区分退步、证据不足和晋级。
- `latest.json`：完整学习恢复点。`best.json`：最近验收成功的部署组合；初始也保存底座。`event-agent`只读取部署组合。

短测试只能确认执行和训练连通，不能证明经济提升、已接近DECEM胜率或能长期持续收敛。

## 夜训前最后复查

对照market3、plan_rl、plan_compare和经验保持失败记录，再查出两处具体缺口：

- 路线暂时占用导致后续事件重新排队后，普通范围已满会把它丢掉。已让有效的已预约后续事件独立保留，并验证路线释放后原事件只处理一次。
- 上述49条短测中的11条后续对照全部只有Keep/Cancel，并非已证实能够探索不同生产修订。它们发生在日初雇工过期、当天维护尚未执行的时刻。现已在共享执行入口推迟日初事件选择，等真实维护回执后再看候选，避免暂态缺工消耗唯一后续机会。

同时统一了同轮best/latest的后续刷新标志；续训更改监控局数时会重新计算监控，避免混用缓存口径。奖励、对手和经营候选没有另起一套。

本轮历史问题复核结果：

| 历史失败 | 当前对应约束 |
|---|---|
| market3交易样本挤占生产，采购与需求脱节 | 没有独立买卖策略样本；采购由当前维护与具体后继材料需求产生，真实现金/库存约束保留 |
| plan_compare局部标签直接接管整局 | 主采集使用已验收组合；候选只替换一个范围及同批次一次后续修订，整套独立验收 |
| 更新了权重却没测当前确定性选择 | 更新后冻结两套权重，实测实际首选，验收前不再更新 |
| 旧继续策略标签混用、局部保持不能保护整局 | 标签含继续版本和条件前缀；失效标签清除，已验收部署模型冻结 |
| 胜负目标与现金门槛不一致 | 只以终局比赛得分学习/晋级，现金与工作统计仅诊断 |
| 验收结果被反复拿来训练 | 训练/首选补测与初筛/独立复核种子分区，验收对局不进入bank |
