# mixed-production-v7

> 当前训练机制修订见 [经验与对手保留修订](mixed_v7_retention.md)：对手入池与冠军分离、分组经验库、分层探测采样。下文原 v7 的容量与采样说明以修订文档为准；旧模型可续训。

## 目标与范围

增加有区别的生产探索，保持投入与执行的连贯性，用实际收益学习，并让确定性执行保留能力。
v7 不增加强制开局投资或等待惩罚。已有项目的可执行工人路线仍沿用 v6 调度约束。
本版不采用 Python baseline、外部示范或验证集轨迹训练。

## 策略与探索

场景 96 维，候选 32 维。候选最后一维保存类别编号，新加 16 类策略头：

| 编号 | 类别 |
|---|---|
| 0 | 等待 |
| 1 | 补货维持 |
| 2 / 3 | 作物 / 动物扩张 |
| 4 / 5 | 转产 / 退出 |
| 6 / 7 | 雇工 / 开地 |
| 8 | 返仓 |
| 9 / 10 | 作物 / 动物服务 |
| 11 | 混合服务 |
| 12 / 13 | 作物 / 动物收获 |
| 14 | 混合服务及肥料衔接 |
| 15 | 收获续种 |

类别互斥，优先归入混合肥料、混合服务、续种、收获等较具体类别。
只对存在合法候选的类别分配概率。联合概率：`π(候选) = π(类别) × π(候选 | 类别)`。
确定性执行先选概率最高类别，再选该类别内最高概率候选，不对所有候选直接取全局最大值。

训练行为分布：`b = (1-ε)π + εq`，默认 ε=0.2。
q 在补货、扩张、转产和路线类别中先均匀选类别，再均匀选该类具体候选。
等待、退出、雇工、开地仍能通过 π 被选择；若无适用探索类别，该决策退回纯 π。
PPO 保存旧 b 的 logp，更新时重新计算新 b；不能把探索动作伪装成从纯 π 采样。
纯策略 entropy 正则权重 0.001，PPO clip 0.1，KL 停止 0.02，梯度裁剪 0.5。

新增场景信息包含各品种距离首次成熟的最短时间、剩余新项目预算、待启动数量。
动物投资价格特征使用 MILK/WOOL/EGG，而非不存在的 COW/SHEEP/GOOSE 产品报价。

## 生产投入与路线

- 每日新建/转产项目订单预算为当日首次观测现金的 25%，按保守订单报价累计；实际付款仍由原引擎处理。
- 每日最多批准 2 个新建/转产项目，同时最多 2 个未确认启动项目。
- 补货为既有生产服务，使用真实可负担性检查，不占新项目预算。
- 启动未确认的项目保护最长 24 步，期间不生成替换/退出该项目的候选；确认启动或超时后可重新安排。
- 雇工候选按已有负载估算需要的人数；不因存在单个小项目就默认需要第二名工人。
- 买入只发订单；真实库存到货后才能生成使用这些物料的路线。失败采购不虚构库存。
- 工人路线沿用资源/地格互斥、连续动作、回执核对、仓库溢出保护；跨夜重规划。
- 有合法任务路线就选择具体路线，单候选直接执行；无可执行任务可以等待。投资层始终保留等待。

这些是控制探索损失的初始约束，不是精确全赛季排程，也不能保证项目盈利。
路线搜索仍为最近 8 个地格、宽度 3、深度 4 的有界搜索，模型只能选择生成的候选。

## 现金回报

训练目标改为实际自身现金增长，竞争力通过对手和晋级检查衡量。
每个策略决策记录 `(step, cash, value, action, behavior_logp)`。
相邻决策间 `r = (next_cash - cash) / 10000`；最后一段直到 step 719，终局 value=0。
该项包含采购、雇工、销售及其他实际结算，不添加工作量或购买次数奖励。

使用 gamma=1 保持整季现金目标，GAE trace 按真实经过回合计算：

```
delta = r + next_value - value
advantage = delta + 0.997^elapsed * next_advantage
value_target = advantage + value
```

同一回合的投资/工人决策 elapsed=0；不同间隔按实际时间衰减。
另保存 `mc_return = (final_cash - cash_at_decision) / 10000`，供独立成功经验辅助学习。
这不能精确拆分共享路线的项目因果收益；没有把共享成本重复记成多份项目奖励。

## 自生成成功经验

每 4 个训练种子中，1 个种子的双座位对局使用确定性当前模型（32 局配置中为 8 局）。
其他局使用探索策略；当前模型自对弈的双方样本可以进入 PPO。
历史对手始终确定性执行，不进入 PPO。确定性经验局也不进入 PPO。

经验来源是这些训练局中当前/历史模型自身的决策，要求终局现金 > 3000 且有实际收获。
每条保留样本还要求未来实际净现金回报 > 0，且选择不是等待。
每局按时间顺序稀疏保留最多 32 条，按使用过的作物/动物品种和混合路线形成粗略风格分组。
最多 16 局经验，每种风格最多 2 局；同种子同座位不重复保存，优先保留真实利润较高的局。

每次 PPO 更新之后，均匀抽经验局再抽其中决策，最多一个 256 样本辅助批次：

```
weight = clamp(mc_return - current_value, 0, 1)  # detach
aux_loss = -0.05 * mean(weight * log π(saved_action))
```

辅助损失使用纯策略 π，单独一次优化器更新；不使用旧经验计算 PPO 比率，不对旧经验做 critic 回归。
经验库为空或无正优势时没有辅助更新。成功对局并不证明每个动作正确，正优势也是近似；小权重与类型限额用于限制影响。

## 对手池、验证、恢复

对手比例仍为约 25% heuristic、25% 当前模型、50% 历史模型；同种子交换座位。
历史池以第 0 轮自身模型启动，通过晋级才添加，最多 4 份权重。
初始历史模型未必强，随着晋级才有机会增加竞争压力。

固定验证集默认每 5 轮和最后一轮运行四组，每组 8 局：

1. 当前模型确定性 vs heuristic。
2. 当前模型纯策略随机采样 vs heuristic（不加探索分支）。
3. 冠军确定性 vs heuristic。
4. 当前模型确定性 vs 冠军。

验证不加入经验库、不更新参数，使用独立随机流。
晋级要求确定性对 heuristic 每局有工作和收获、平均现金 > 3000、平均现金差超过冠军对同一对手的结果，同时直接对冠军平均现金差 > 0、胜率 > 50%。
有限种子门槛不能保证泛化或单调变强，最终测试使用新的种子和外部对手。

检查点 schema：`mixed-production-v7-ppo-v1`；特征/动作契约：`mixed-routes-96x32-hierarchy-cash-v3`。
保存网络、Adam、训练 RNG、配置、历史池、完整经验库。v5/v6 模型不兼容，旧 run 不会被覆盖。

## 文件与诊断

- `learning/policy.rs`：分类头、混合概率、PPO、现金 GAE、辅助损失。
- `learning/experience.rs`：盈利轨迹筛选、类型限额、抽样和持久化。
- `pipeline/planner.rs` / `executor.rs`：项目限制、分类、执行和启动确认。
- `pipeline/rollout.rs`：CPU 环境、按模型/行为模式分组的 GPU 推理、数据隔离。
- `pipeline/league.rs`：冻结对手与晋级。

`projects_requested / projects_started / expired_projects` 分别为新项目批准、真实启动确认、缺货过期次数。
`policy_wait_probability` 是每席存在多个候选的模型决策中，纯策略等待概率的平均值；单候选自动执行不计入。
`selected_groups` 是每席实际模型类别选择次数，不等于任务完成次数。
`experience_episodes / new_profitable_episodes / imitation_samples / imitation_loss` 说明辅助学习的数据与执行情况。
`update_seconds` 含 PPO 与辅助学习，`ppo_seconds` 单列 PPO，验证耗时单列在 evaluations 中。

长训练前看短实验的实际收益、生产完成情况、确定性与采样表现。机制测试通过不代表经济效果已经改善。
