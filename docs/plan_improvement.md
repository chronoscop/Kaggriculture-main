# 逐步组成完整经营策略（plan-improvement-v3）

目标：在已有生产持续运行的前提下，发现更好的投入或生产衔接方式，让网络根据局面选择它；通过完整对局后，把这个选择保留下来，继续寻找下一处改进。

## 本次修正

v2 把只在少量状态上学习过的候选网络立即用于整局采集。局部学会等待后，开局也被改成等待；即使验证失败，下一轮仍沿退化策略采集。局部对照有价值，不代表网络可以接管整局。

v3 的循环是：

1. **已验收组合产生局面。** 初始组合使用当前规则经营底座。训练网络只提出备选，不控制基础对局。
2. **同一状态只改一次。** 分支换一个合法生产方案，双方随后按同一组冻结策略继续经营至赛季结束；对手随新状态正常反应。
3. **网络学习实际收益差。** 目标为胜/平/负得分变化，加上 `0.1 × 归一化终局现金差变化`。新数据与同版本保留数据共同回归；收益相同的对照也保留。未测试的候选没有伪造的好坏标签。
4. **一次只验收一个经营机会。** 网络在该机会根据局面选择方案，其他机会保留已验收模型。比较的是这套完整候选策略与当前组合，而非单条路线。
5. **通过才合入。** 同种子、换座位、同一冻结对手集合先初筛，再用独立种子复核。通过后保存该机会的冻结网络，下一轮从新组合继续发现改动。

这仍是神经网络训练；最终策略由多个已验收、根据当前局面决策的网络组成。不是直接部署参数搜索结果。

## 接管范围

当前把 719 次状态转移划成 16 个窗口：

```text
[0,6), [6,12), [12,24), [24,48),
[48,96), [96,168), [168,240), [240,288),
[288,360), [360,432), [432,504), [504,552),
[552,576), [576,600), [600,624), [624,719)
```

**每个窗口内，第一个有多个合法候选的经营机会最多接管一次。** 其余决策继续由经营底座及此前已验收的安排执行。分支复制前就消耗这次机会，防止续演时再次执行同一改动。窗口覆盖开局、扩张、衔接和收尾；它不是“每天所有决策都交给一个网络”，也尚不是现金到账等语义事件的分类。

每次晋级只替换一个窗口的模型，其他窗口的权重不动；最多 16 个模型，反复替换不会形成无限递归的历史调用。早期决策改变后，后续模型会看到新局面，这部分连带影响由整局验收衡量。

现有候选仍来自批量投入、已有地块续产/转产等计划生成器，路线与销售继续使用当前执行规则。本次修复训练与保留机制，没有声称覆盖所有可能的生产和交易策略。

## 晋级与数据保留

- 训练对手为规则经营底座、当前已验收组合、上一版组合；移除初始时重复的身份。失败候选不会进入对手集合。
- 至少两个不同训练种子的实测正收益支持，并且已测净收益为正，才让一个窗口进入整局验收。经验支持不直接晋级。
- 初筛和复核都要求胜平负得分改善，或得分不降且平均归一化现金差提高超过 0.002；同时检查不同种子、不同对手及生产停摆情况。
- 固定监控种子不参与训练，也不用于候选晋级；监控只在已验收组合改变时重新运行。
- 对照标签依赖后续执行策略。晋级后清空当前对照经验库，旧证据仍在 `comparisons.jsonl`，已学会的行为保存在冻结模型中。
- 有限对局验收可以拦截明显退步，不能保证所有未见市场和对手下的收益单调上升。

## 运行

本机已构建 `plan-train` 和 `plan-agent`。需要重新构建时：

```bash
export PATH="/tmp/route-rl-rustup/toolchains/stable-x86_64-unknown-linux-gnu/bin:$PATH"
export CARGO_HOME=/tmp/route-rl-cargo
cargo build --manifest-path native/Cargo.toml --release --features train --offline --bin plan-train --bin plan-agent -j 4
```

开新目录运行；v1/v2 检查点不兼容，不能把旧版未验收 learner 当成新底座：

```bash
mkdir -p runs/plan_improvement_trial
native/target/release/plan-train \
  --out runs/plan_improvement_trial \
  --iterations 100 --games-per-update 16 \
  --branch-points 2 --alternatives 1 \
  --workers 7 --device cuda \
  --epochs 8 --batch-size 64 --learning-rate 0.0003 \
  --eval-every 5 --eval-games 8 --confirm-games 16 \
  --seed 1200 --eval-seed 1100000000 \
  > runs/plan_improvement_trial/train.log 2>&1
```

100 轮包括 1600 局基础对局，每局最多两个续演分支，另加有希望候选的初筛/复核局；不是只有 1600 局计算量。CPU 并行跑环境和推理，CUDA 更新网络。小网络每轮数据量有限，GPU 利用率本身不代表学习效果。

续训使用 `--resume runs/plan_improvement_trial/latest.json --out 新目录`；`iterations` 是**额外**轮数。恢复网络、Adam、已验收组合、上一组合、同版本经验、采集种子及随机状态。恢复时使用检查点内的采集/评估 seed；其他训练规模参数采用命令值。

## 看结果

- `evaluations.jsonl`：`promoted`、`accepted_revision_after` 是是否合入改进；`candidate_slot` 指出本次改变的位置。看 `screen` / `confirmation` 中的真实整局增益。
- `deployed_vs_rule`：固定种子下已验收策略的现金、得分和衔接结果；未晋级时缓存保持不变，这是同一策略的同一组结果，不能误认为网络没有更新。
- `metrics.jsonl`：基础局使用已验收组合；看 `slot_coverage`、`better_alternatives`、收益差回归误差、采集耗时。训练局种子变化，不用相邻轮现金直接判断强弱。
- `comparisons.jsonl`：每条分支的计划、执行结果、终局资金、完整候选集与 `incumbent_revision`。
- `latest.json`：完整续训状态，含训练中的 `model` 和已验收的 `deployment`。
- `best.json`：最近通过两阶段验收的完整检查点；初始也会保存底座。不是按单次最高现金挑选。
- `checkpoint_XXXXXX.json`：每次验收轮保存完整恢复点。

`plan-agent --checkpoint 文件` 只加载 `deployment`。即使传 `latest.json`，也不会使用未通过验收的训练中权重。该程序仍是持久 JSONL 对战入口；比赛打包需按比赛协议另行处理。

## 本次实现检查

20 项针对性测试通过，覆盖单槽替换、分支/部署一致性、收益差回归、版本隔离、拒绝晋级以及检查点恢复。额外运行了 2 轮 CUDA 链路检查：32 局基础对局、64 条分支，16 个窗口均有覆盖，网络权重更新、基础局无零收获；未达晋级条件时部署权重保持不变。该检查证明流程可运行，不作为经济效果提升的结论。
