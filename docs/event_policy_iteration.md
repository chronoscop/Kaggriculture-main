# 固定参考策略的经营计划学习

当前入口：`event-train` / `event-agent`；训练检查点 `event-policy-iteration-v5`，执行契约 `event-shared-policy-season-scope-v5`。

## 修改依据

先复核了 `competition_replay_review.md`、`plan_compare_trial_review.md`、`event_plan_pair_overnight_review.md` 及当前实现。上次151次更新没有晋级；采集约7小时22分，网络更新总共54秒。继续网络周期变化迫使主决策标签失效，终局分支多次展开，经验和验收单位也不一致。这些是已确认的问题；不能保证它们解释了全部停滞。

已有批次生产、共享资金/物料/工时约束、混合路线和真实回执继续使用。DECEM回放支持学习连续生产、条件转产和现金周转的行为目标，不能确定其训练算法。

## 一个完整的更新协议

1. **参考策略 πₖ 固定。** 完整已验收版本生成基础局面，对手名单也在这一周期固定。未晋级不会刷新继续网络、切换对手或作废标签。
2. **一套网络。** 首次安排与同批次后续修订共用参数；资源、已有承诺、市场和事件身份仍进入现有输入。当前接管范围预先固定为四段赛季的收获机会（scope 0–3），各自最多一次同批次后续修订，共最多8次决策。其余经营由冻结的已验收底座执行。
3. **真实同状态对照。** 对参考轨迹选少量事件，优先测当前网络不同于参考的首选，同时保留另一种生产方向。只改这一次，之后全部由同一 πₖ 完成到step719；终局胜1/平0.5/负0之差是唯一标签。现金和产量只作诊断。
4. **修订状态也有学习来源。** 探索第一段安排时，记录它真实到达的同批次后续事件。最多再测一个修订备选，其参考结果复用刚完成的那条轨迹；之后仍全部由 πₖ 执行，不再递归分叉。标签记录条件前缀，不冒充已验收轨迹状态，也不更换后续网络。
5. **预算是硬限制。** 默认每局最多4条额外终局分支、最多1440个额外模拟step，两者取更严格的限制；后续对照也占用这个预算。一条分支放不进预算就不启动，绝不截断后伪造终局标签。16局每轮采集至多34544步，约48局完整模拟工作量，不含独立评估；旧夜训平均约139局/轮。
6. **两类证据各自保留。** 首次安排/后续修订分别有受保护的elite与recent，回放两者都存在时平衡抽取。每个经营桶保留历史强证据，同时允许同强度的新证据更新其余名额。仅完整策略晋级后清空条件已改变的活动标签；历史JSONL和旧检查点保留。
7. **整套候选验收。** 每次初筛冻结一个网络，用它同时控制上述全部声明范围。以同种子、换座、同对手的完整对局比较 πₖ 与候选；不再从少数正向单点挑一个窗口拼接部署。采集、分支与部署复用相同事件调度/候选/执行入口。局部对照不等于完整策略变强，必须过完整验收。
8. **独立复核可续接。** 初筛得分改善后保存冻结候选。独立复核最多三次累计查看：每个对手16/32/64局（默认），在后续评估周期继续，同一候选不会被正在训练的网络替换。复核数据不进入训练；检查点包含候选、已完成样本和种子游标。不能重新开始同一个不确定候选无限刷显著性。
9. **通过才推进。** 通过后整个共享策略成为 πₖ₊₁；学习器回到这份实际确认的权重，并清空旧Adam和失效活动标签。未通过维持 πₖ 和本周期数据；学习中的网络可以继续更新。

这里统一的是**有界经营事件范围内的完整策略版本**；没有让新网络无条件接管所有经营动作。扩大范围必须重新覆盖采集和整局验收，当前没有自动扩范围开关。初始开局及大量常规生产仍由已验收底座负责。

## 验收限制

只以比赛得分验收，没有绝对现金、现金差、产量或“改善种子必须过半”的硬门槛。复核沿用按独立种子聚合的单侧配对符号翻转检验，三次查看分配单候选0.05预算；依赖配对差值对称等假设，不控制整晚所有不同候选的总错误率。未通过不覆盖已验收策略，不代表已证明候选没有价值。

训练没有提供长训必然单调提升的保证。有限范围、终局胜负标签稀疏、工时预估误差、单点对照组合后的相互影响仍是实验要判断的限制。

## 构建与实验

在项目根目录执行。推荐先100轮，读取整套候选的初筛/独立复核；不要再用底座现金是否变化替代候选学习情况。

```bash
export PATH="/tmp/route-rl-rustup/toolchains/stable-x86_64-unknown-linux-gnu/bin:$PATH"
export CARGO_HOME=/tmp/route-rl-cargo
cargo build --manifest-path native/Cargo.toml --release --features train --offline \
  --bin event-train --bin event-agent -j 4

mkdir -p runs/event_policy_trial
native/target/release/event-train \
  --out runs/event_policy_trial \
  --init-from runs/event_plan_trial/latest.json \
  --iterations 100 --games-per-update 16 --workers 7 --device cuda \
  --branch-points 2 --alternatives 2 \
  --branch-steps-per-game 1440 --max-branches-per-game 4 \
  --epochs 8 --batch-size 64 --learning-rate 0.0003 \
  --eval-every 5 --eval-games 8 --confirm-games 16 \
  --seed 200000 --eval-seed 1800000000 \
  > runs/event_policy_trial/train.log 2>&1
```

训练种子200000和评估种子1800000000用于新实验；初始化会把训练游标设为旧游标与新seed的较大值。`iterations`是额外更新次数。100轮含1600局基础采集，最多6400条额外分支（仍受step预算），另有评估。无需Python采集；CPU并行模拟、CUDA更新。

```bash
tail -f runs/event_policy_trial/train.log
```

### 初始化与恢复明确区分

- `--init-from`：旧v4事件检查点，**只允许没有已验收事件补丁的版本**。保留v3已验收底座，旧事件学习器权重作为提议网络起点；旧双网络标签、Adam、待复核状态不沿用，新轮次从1开始。源文件不修改。当前event_plan_trial和pair_overnight均没有事件晋级，符合这个边界。
- `--base-checkpoint runs/plan_improvement_trial/best.json`：保留v3底座，新的事件提议网络从初始权重学习。
- `--resume runs/event_policy_trial/latest.json`：仅恢复新v5完整检查点，包括Adam、有效经验、冻结待复核候选与种子游标；必须新输出目录。命令中的`--init-from`删掉，换为此项即可，轮数仍是额外轮数。恢复的学习率/种子以检查点为准，待复核候选继续使用它冻结时的复核规模。
- 原v4已验收部署仍可由`event-agent`读取其当前v4执行契约，不会把学习中权重当部署权重。

### 文件口径

- `metrics.jsonl`：基础轨迹是 πₖ；`continuation_revision` 未晋级应保持不变。查看两类pair数量、当前首选实测数、模拟步数、耗时、两类经验保留。网络拟合指标属于训练数据，不是泛化胜率。
- `comparisons.jsonl`：每条包含scope、真实候选、实际终局胜负、继续版本、事件身份、是否条件探索。没有人为现金奖励或未完成终局标签。
- `evaluations.jsonl`：`candidate`/`incumbent` 是完整策略初筛；`confirmation_*` 是冻结候选的独立复核；`candidate_iteration` 可以连续多次相同，因为正在复核同一份模型。`deployed_vs_rule` 在无晋级时可完全不动。
- `latest.json` 是完整训练恢复点；`best.json` 的`deployment`是最近验收通过的整套策略。部署入口只读取`deployment`。
- 被独立复核拒绝/仍不确定的候选另存`candidate_*_reject.json`或`candidate_*_inconclusive.json`作审计，不自动无限追加验证。
