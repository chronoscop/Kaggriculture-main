# 按资源与市场条件提案：夜间实验

## 这次解决什么

上一轮审计证明收获接续存在执行冲突，修正后8个案例的后继产出地块5/11→10/11，但一场由胜变负。更可靠地兑现转产，不代表转产本身值得做。

这次修改候选生成层，沿用稳定续接策略、完整菜单终局对照、独立胜负验收与冻结底座。与DECEM回放对应的是：延续有价值的现有生产，在条件合适时小批量转产、备料并衔接路线。不能把该行为归因于我们不知道的DECEM训练算法。

## 代码变化

- `plan_menu::build_contextual` 用相同局面下的续种机会作为比较基准，根据季末前可用时间、当前及公开供需估计价格、种子/动物/饲料成本、备料与服务工时缺口，筛选不同经营方向。
- 保留冻结底座与Keep，提供续种（已有承诺时可取消未来部分继续当前生产）、换作物、单格转养，以及同一方案多续种一轮再启动的对照。剩余名额由资源估计排序补充不同规模/品种，最多6项。季末不可行的方案不补假候选。
- 去掉新菜单中按日期轮换动物品种、优先给动物立即/延期占两个名额的逻辑。旧部署仍走旧逻辑。
- 不把估计当真值。估计没有精确模拟将来的价格、工人调度和对手；只是短名单排序。负估计的方案仍可参与各类探索，标签一律为真实终局胜=1/平=0.5/负=0。
- 不新增自由交易动作。实际采购、现金保留、取料、收获衔接仍由同一个计划和资源账本约束。
- 每个学习菜单完整执行全部分支，训练与部署都只能在这份菜单选择；新增菜单上限同步到学习校验与模拟预算，不能让多出的选项没有标签。
- `menu_opportunities` 按完整集合去重，记录有更好方案的局面数，以及各类方案better/worse/tied。它描述当前采集局面，不是泛化胜率。
- `--max-seconds` 在轮次边界保存退出，输出`finished.json`。既有每轮原子保存latest、独立验收后保存best机制保留。

## 兼容性

检查点 `event-policy-iteration-v12`；候选编码 `event-menu-resource-ranked-v3`；采集合同 `complete-resource-ranked-menu-v4`。新部署合同 `event-resource-ranked-menu-v1`。

旧经验/Adam/待复核候选不能用`--resume`导入。旧v10/v11部署仍保留原候选及执行语义。迁移入口只接受没有旧菜单接管的已验收底座或本版检查点；已验收的旧菜单策略仍可用event-agent部署，不把它静默改成新菜单。

默认初始化文件 `runs/event_policy_conditional_trial/best.json` 的已验收策略为legacy revision 1，文件iteration=0：它不是25轮失败实验的最新提议网络。新提议网络从零评分头开始，初始确定性选择仍是冻结底座。整个夜间实验另建目录，旧文件不改。

## 运行（screen内）

```bash
bash tools/run_contextual_overnight.sh runs/event_policy_contextual_overnight 10
```

脚本先构建当前版本，再运行约10小时（含初始化、不含编译；允许超出一轮的时间）。10000轮只是上限，到时不开始下一轮。每轮16个训练条件（8个新种子换座），各有底座与候选前缀两条完整轨迹；每条件最多2份完整菜单、12个终局分支、8640个分支模拟步。实际对局/分支数取决于耗时和有效事件，不能预先等同于固定局数。

默认7个CPU采集线程、CUDA网络更新、epochs=8、batch=64；每5轮固定面板和独立晋级验收。GPU更新很短，耗时主要是CPU真实分支模拟，低GPU利用率本身不代表未用GPU。

```bash
tail -f runs/event_policy_contextual_overnight/train.log
```

- `latest.json`：学习器、经验、优化器、已验收策略和待复核状态，用于续训。
- `best.json`：最近独立验收通过时的检查点；实际部署读取其中deployment。
- `observations.jsonl`：学习中网络的固定面板成绩；不要把少数固定种子上涨当泛化。
- `evaluations.jsonl`：独立验收；没有promoted时best不动是保护行为。
- `metrics.jsonl`：看menu_opportunities、complete_set_choices、candidate_coverage，区分提案无收益和网络选不准。
- `finished.json`：正常退出时的轮数和耗时；没有它需检查日志是否报错/被中断。

本版本续训仍需新目录，并显式使用`--resume .../latest.json`；`--iterations`是追加轮数，`--max-seconds`是本次进程时间预算。

## 明早怎样判断

优先看真实独立对战得分有没有改善；其次看菜单里有效选择出现多少、网络选择这些方案后的局部收益和整局收益是否一致。产出数、转产数、现金仅用于诊断。如果仍无独立收益，应保留失败证据，而不是把更多轮次或更低loss称为有效。

这是一场受预算限制的完整训练实验，**尚未证明稳定收敛或达到DECEM水平**。本轮测试负责确认状态影响提案、真实资源约束、旧部署保留、完整菜单学习及保存/恢复链路，不代替经济收益验证。

## 本轮实际检查

- Release回归：148项库测试、5项部署入口测试、16项训练入口测试通过。
- CUDA连通性：2个训练条件、4个完整六项菜单，完成采集、更新、评估和保存；随后从latest恢复，完成下一轮并在时间预算到期后于轮次边界保存。两次未晋级，已验收策略保持不变。
- 连通性首轮4份菜单没有更好于参考的选择；固定面板的少量变化不能当收益证据。该检查不支持宣称方案已有效。
- 恢复检查确认新版本经验与优化器可读取，完成退出输出finished.json。时间限制允许当前轮超时，1秒测试预算实际完成了约154秒的一轮，符合软上限设计。
- 原conditional实验的latest、best、comparisons的SHA256保持不变。
- 夜间训练尚未启动，由用户运行脚本。
