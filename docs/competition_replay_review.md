# 比赛前复盘：强回放、现有模型与训练问题

日期：2026-09-27。范围：market3 rule 第 100 轮、learned 第 50 轮；历代 v7 复盘；五场 DECEM 原始回放；现有模型对 farm2945 的新行为对照。本次未修改训练实现或检查点，没有启动训练。

## 1. 结论

当前存在两个需要分别处理的问题：

1. **策略能选择的生产规模、路线信息和计划衔接，比强回放窄得多。** 即使把当前 PPO 训练稳定，也不能选出候选生成器不提供的开局、扩张和工作安排。
2. **训练没有充分保护已经学会的确定性经营能力。** 对手和经验池的多次改进有作用，但并没有完成策略保持；开放高频交易后，训练数据和更新预算进一步偏向交易。

这不是简单的“训练还不够”或“对手不够强”。也不能把所有历史运行说成越练越差：早期 v7 长训练确实从约四万推进到了六万量级，之后才出现平台、局部退步；market3 learned 到第 50 轮也在提升，只是提升的能力和效率明显不符合当前比赛需要。

## 2. 强策略实际强在哪里

### 2.1 五场 DECEM 原始回放

原始文件在 `replay/113434582.json` 等五场；既有查看器 `/tmp/farm_replay_analysis.html`。本次重新核对原始分析口径及逐日统计。

- 五场第 0 天均成功放养 2 牛、3 羊，种 6 格甜瓜、9 格小麦；第 1 天再种 4 格甜瓜、1 格小麦。**前两天形成 25 格生产。**
- 开局有农场主加 4 名雇工；中期多数日约 12 名雇工。
- 首次成功扩地全部在 t=149，后续扩地约 t=217–254。
- 每局确认的收获后续种事件分别为 183、212、197、222、192 次；间隔中位数均为 1 回合。
- 同一地格可以先种小麦，再放养动物，后期清掉牧场重新种作物。
- 商店条件不同，后续投入发生变化；有纱线店的一局全季放羊 15 次，另四局各 3 次。不是仅按当下最高售价扩张。
- 最后两天没有新种植；最后一天没有 FEED/CARE 指令，体现季末退出。
- 终局现金分别为 123108、95707、135231、83049、117478。

具体连续生产例子：113434582，第 10 天工人 12，t242 取小麦 → t245 喂养 → t247–249 喂养、照料、收肥 → t251–252 给附近作物施肥、浇水 → t258–260 收获、续种番茄、浇水。关键是材料、工时、土地用途及下一轮产出能一起兑现。

**证据边界：**回放能说明行为，不能证明对方使用 PPO、行为克隆、神经网络排路，或某种“半 RL”训练方法。五场不是随机样本，不能用它们估计总胜率，也不能把其中现金直接与我们的不同对手现金作实力排名。

### 2.2 本地强参考源码提供的解释

`agents/farm2945_resilient_response/main.py` 是另一份本地参考，不能当成 DECEM 的源码。它包括路线模板和多层状态反馈调整。值得借鉴的是可检查的计划机制：

- `_db_schedule` 根据将来的实际访问机会安排种植、浇水和收获，检查作物生长期与季末。
- `_db_quote` 把已公开商店、双方可见生产、待投入批次和自身新增供给放进保守收益估计。
- `_db_reserve` 为饲料、已提交采购和雇工等保留现金。
- `_db_reconcile` 通过后续真实观察确认种植成功、取消过期计划；不把发出采购请求当成已经获得材料。
- `_sc_plan` 及其执行层把换动物对应的采购、取货、放养动作连起来。

这些是代码能直接证实的机制；不能由此断言其作者采用了哪种训练方法，也不能认为文件顶部每个开关都处于启用状态。

**小样本限制：**这是一组机制诊断，不是六个独立种子。不能据此断言三个版本总体强弱次序。尤其 rule100 的自身现金比 rule40 低，但参考现金也降低，平均现金差反而缩小；共享市场下不能只按自身现金判断两者对战能力。是否退步仍应结合既有多种子对战，而不是拿这两局下统计结论。

## 4. 确定的实现缺口

### A. 候选生成限制了可学到的生产规模

`native/src/pipeline/planner.rs`：

- 启动或改变非空生产项目：每天最多 2 个，待落实项目最多 2 个。
- `executor.rs` 每天开头把扩张采购预算设为当时现金的 25%；日内新增回款不会直接重设这个预算。
- 雇工目标为 `ceil(labor_load / 14).clamp(1, 8)`，包含农场主，因此最多提供 8 名总工人的目标；还只在每天前 9 个小时提供雇工候选。
- 开地需要已有至少 12 个项目；新地块候选只取距离仓库较近的 3 个位置。
- 投资决策通常每 6 回合一次，现金增加或新一天才获得额外机会，每次选择一个投资候选。

这些是设计约束，不是 PPO 能靠更多训练突破的边界。不能简单把所有上限删掉：需要把可服务工时、路线、投入资金和回款一起预算，否则会造成过量投资与烂尾。但用“每天两个项目”代替真实承载能力，确实排除了回放那种可行开局。

### B. 路线筛选和表示没有充分表达经济价值

`planner.rs::route_problem` 使用最近 8 个目标、深度 4、每层保留 3 条的搜索。预筛分数：

```
4 × 工作次数 + 2 × 收获件数 + 3 × 肥料复用次数 − 行走次数
```

它没有考虑收获的是牛奶、羊毛还是小麦，也不看市场价格、投入成本、销售回款的急迫性。RL 只能在已经留下的候选中选择；被提前剪掉的路线不能靠策略网络找回来。

`encoding.rs` 的路线特征主要为总时长、行走/工作次数、地格数量、种养任务数、总收获件数、续种次数、取货/种子总数、终点和各指令计数。**没有路线按商品划分的收获/交付量，也没有服务目标序列或目标商品身份。**全局价格信息无法充分补上“这条候选具体产生什么”的缺失。

这不表示网络完全不能间接辨别路线，但它没有足够直接的信息来可靠比较按商品价值不同的路线。增加对手市场信息，不能自动修复这个候选表示缺口。

### C. learned 的交易粒度挤占了生产学习

同为第 41–50 轮、32 局/轮、epochs=2：

| 指标：每轮平均 | rule | learned |
|---|---:|---:|
| PPO 样本数 | 7574.5 | 44825.4 |
| 交易样本占比 | 0 | 77.6% |
| PPO 小批次更新数 | 60.2 | 351.2 |
| 采集时间（秒） | 25.39 | 69.43 |
| 更新时间（秒） | 1.01 | 6.33 |
| 推理调用次数 | 4768 | 23008 |

learned 的总调用更多，平均推理批次只有约 4.36，并没有通过新增交易获得高效的大批次计算。相同“50 轮”也不是相同优化预算。

最近十轮的 80 局确定性训练探测中，learned 平均每局选择约 **973 次买入、447 次卖出，主动停止交易 0 次**。这不表示所有订单都成交，也不表示每一次往返交易都亏损，但清楚说明策略偏向高频交易。

本次新回放的具体例子，learned50 座位0：

- t0 买 10 小麦、1 肥料；t1 又卖出这些商品。
- t2–5 每步买 1 小麦、1 肥料；t6 又卖出累计的 4+4。
- 第一日结束现金仅 **11**，仓库有 **37 小麦、17 肥料**，地上只有 **2 格甜瓜**，没有动物。
- 全季请求买小麦803、肥料473；请求卖小麦814、肥料472，生产规模仍小。

不能仅把买卖额相减称为交易损失，因为库存与生产消耗也必须记账。可以确认的是：原料购买和生产需求脱节、资金大量进入周转交易。

触发机制也有放大效应：`Trading::begin_if_due` 保存的是**本次交易前**的市场/现金/库存锚点；下一回合自己的买卖也可能触发价格变化、到账或库存增加事件。每阶段每商品一单只限制阶段内部，阻止不了跨回合反复买卖。

生产和交易虽然共用独立于 critic 的 actor，但仍共享 actor 的 context、候选编码和评分参数。当前把所有 PPO 行平铺抽样，因此交易行变多会同时增加它们的训练份额和总更新次数。不能只提高 GPU 利用率解决这个建模问题。

### D. 成功经验保留没有变成稳定的能力保护

经验库已有受保护 elite/recent/diverse 名额；旧“全部被近期样本挤掉”的问题不能再拿来解释一切。但实际辅助学习仍为：

```
weight = clamp(历史实际后续现金回报 − 当前 critic 估计, 0, 1)
```

而且每轮所有 PPO 更新之后，只做一次最多256行、系数0.05的辅助更新。

固定取 rule40 银行的48局 elite、1536个决策，分别由40/100模型计算：

| 同一批旧成功状态 | 第40轮 | 第100轮 |
|---|---:|---:|
| 平均辅助权重 | 0.450 | 0.259 |
| 权重为零比例 | 28.6% | 56.1% |
| 历史动作确定性一致率 | 73.8% | 67.7% |
| 路线动作确定性一致率 | 64.6% | 55.9% |

已用32行原生 forward 校验离线计算。零权重不自动等于 critic 判断错误，历史轨迹也不一定代表当前最优；但这说明当前实现没有对已证实的关键能力提供独立、稳定的保持机制。整体历史动作概率反而上升，不应描述成所有动作都被遗忘。

小批次 PPO KL 只比较本轮采集策略，不能保证跨几十轮的确定性动作不变，也不覆盖辅助更新后的全部偏移。`best.json` 会保住文件，正在训练的 `latest` 不会因此自动回退。

## 5. 历次路线的收获与失误

| 阶段 | 确实解决/尝试解决的事 | 没有解决的事 |
|---|---|---|
| v5/v6 自建规划器 | Rust采集、项目和路线选择、工作执行 | 从一开始就有较窄的生产候选；堵等待不能产生高收益计划 |
| v7 探索与经验回放 | 从零学到有效生产，长训练达到约六万量级 | 随机策略改善不保证确定性执行同步改善；从盈利局抽单步不等于保住完整生产链 |
| retention | 增强经验复用 | 初版容量让长期经验被近期挤掉；后来修了存储名额，学习权重仍有缺口 |
| league/PFSP | 更有针对性的挑战、历史覆盖、冠军复核 | 换对手无法补出候选缺失的开局/路线价值，也不会自动稳定参数更新 |
| independent actor/critic | 修复价值回归直接干扰共享策略表示 | 仍有经验权重削弱与长期漂移，900轮没有超过本轮475冠军 |
| v8 market1–3 | 开放买卖、数量范围、事件机会、对手公开供给信息 | 高频微决策、自己触发自己、生产/交易未分配独立预算；路线经济信息仍缺失 |

既有独立验证：v7 independent 第900轮对475冠军，在16个新种子换座的32局中只赢2局；旧1925也强于新475。详细数据在 [900轮复盘](mixed_v7_independent_900_review.md)。这比只看一次固定现金下降更有说服力。

当前 rule 固定8局：40→100轮，确定性现金49617.75→45409.625，但随机策略29692.5→38054.875，收获件数238.125→304.375。说明“训练没动/完全没学到”不是准确描述；训练分布、执行方式和经济效果没有一致改善。

当前 learned 固定8局：30轮4343.75、45轮10787.125、50轮11406；有进步，但第50轮 rule 为47872.375。两个模式各只有一次训练随机种子，不能据此宣称所有可学习交易方案都不行。

**实施顺序上的失误：**我们多次扩大了探索、对手或市场自由度，却没有先完成规划能力对齐和此前已经发现的保持缺口。在底层承载能力与信用分配不足时继续增加自由度，令模型把更多算力用在局部调整和交易往返上。这需要调整工程优先级，而不是继续换一套训练名词。

## 6. 剩余两天的优先级

### 比赛分支：先解决策略能不能做出好经营

1. 保留现有较强检查点与本地强参考作固定基准，暂停当前 learned 长训练；不再以新版本名称代替成绩。
2. **优先改善 Rust 候选生成和经济信息：**用可服务的工作窗口、已落实材料、现金与季末回收期，生成批量开局/扩张和续接候选。替换每天2项目、25%现金这类粗限制，不能只无约束提高数字。
3. 路线候选加入按商品的预计交付量、净材料消耗、回仓时间与紧急任务；预筛同时保留收益、资金周转和种养协作方向的候选，避免都按工作次数排序。
4. 保持生产可执行和连续回款，在这个基础上只让模型调整有限的转产、批次规模和销售窗口。市场先保留稳定执行机制，逐步学习有明确资金边界的偏移。不是放弃灵活交易，而是避免同时从零学习高频买卖和生产。
5. 用短的新种子对照决定是否值得训练或提交；判断终局胜负与现金差，同时看具体生产兑现。上限修改会改变旧模型看到的分布，不能假设旧检查点无需验证就能驾驭。

这条路不要求把1.95MB Python参考完整移植，也不要求拿参考生成训练标签；它仍可只做验证。若短期自建 Rust 方案无法接近强参考，就需要明确比赛成绩目标与长期纯 Rust 研究目标的取舍，不能承诺两天靠一轮从零长训练补齐差距。

### 训练分支：底层可行后，独立补稳定性

- 对严格筛选的 elite / 成功状态建立受限保持项，不再完全由当前 critic 一票归零；覆盖训练步，而非每轮结尾一次。
- 保留冻结策略参考与完整更新后检查，必要时降低步长或拒绝明显破坏性的更新；不能全状态锁死旧冠军，否则阻止改进。
- 对生产和交易显式分配抽样/损失与更新预算；纠正交易后事件锚点，避免自触发循环。可先冻结生产参数，只训练交易模块，减少互相干扰。
- 对连续生产计划探索并记录最终兑现结果，减少逐小步扰动整条链。成功片段可以用于保持，不能把旧轨迹直接冒充当前 on-policy PPO 样本。
- 暂不再重写对手调度；用稳定近期对手、历史补短板和少量覆盖即可，先减少同时变化的因素。

这些措施提高可控性，不提供神经网络自对弈“每轮单调提升、无限长训练必然收敛”的保证。比赛交付应是通过独立对照的最好可用策略，不能默认 latest 就是最终提交。
