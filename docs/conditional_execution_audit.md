# 条件计划：原局面执行审计与收获衔接修正

## 结论

25轮无晋级不能归因于门槛过严。旧计划与路线在收获边界存在真实冲突；修正后更多后继生产兑现，但本次抽取的案例没有胜负收益改善。**执行修正不等于学会更好的经营，不建议据此直接夜训。**

此前经验见 `competition_replay_review.md`、`plan_compare_trial_review.md` 与 `event_policy_conditional_trial_review.md`。目标仍是可兑现、可按条件调整的连续生产；不能把更频繁转动物视为接近DECEM，也无法从其回放推断训练算法。

## 如何核对

从原 comparisons 抽取8个案例：2个动物计划未兑现、2个兑现但降低终局得分、2个兑现且提高得分、2个作物计划未兑现。包含11个被选方案的目标地块。

加载每条记录保存的 collection_sources，恢复当时的候选前缀、已验收续接策略、对手与配置。原始重放的8组底座/候选（16条终局分支）全部复现归档现金；再只修改被选方案的收获衔接执行，保持同一选择、同一对手和续接网络。这是按结果抽样的机制检查，不是独立胜率评估。

- 原始重放：`runs/conditional_execution_audit/summary.json`
- 最终干预：`runs/conditional_handoff_final/summary.json`
- 每个目录包含 request、逐案报告和逐步资源/动作轨迹。
- `latest.json`、`best.json`、`comparisons.jsonl` 的SHA256与审计前一致。

## 确认的冲突

旧路线可以在同一路线上先收获、再续种原品种。计划控制器却遇到路线预约就跳过切换；预约解除后，地里已经是新种的原作物。早收路线与控制器要求的最成熟时点也不同。

例：case0 的(1,1)，第469步已完成两次真实收获，地为空，有鹅、饲料、现金、工时，但仍被旧路线预约，第470步又种小麦。case1 的(7,4)，资源在路线安排之后到账，第537步收获后为空且条件满足，旧路线仍在第547步续种胡萝卜。

这些案例说明“模型选了下一批”未必等于“执行器兑现了下一批”。仍不能把全部训练停滞归于此。

## 修改

1. 条件批次把实际库存、现金、工时和期限检查后的后继生产交给路线生成器，尝试同路收获并接种/安置下一批。
2. 只在真实收获回执确认后提交转产；没有达到承诺收获次数，不提前切换。路线无法完成时保留原生产。
3. 资源在路线分配后才到位时，只在真实收获后的空地边界，释放该地尚未执行的旧续种/浇水/施肥。保留路线时间、移动、其他地块和货物动作；不覆盖未完成收获或已承诺的后继路线。
4. 采集与部署使用相同执行标记。新执行合同为 `event-conditional-harvest-route-v1`，检查点v11、采集合同 `complete-conditional-harvest-menu-v3`。旧v10部署保持原执行方式，旧经验不能直接续训解释为新执行结果。
5. 终局胜负目标、独立复核、已验收底座和取消选项保留。没有加入完成率或现金奖励。

|---|---:|---:|---:|
|0|2|0→1|1→1|
|1|1|0→1|1→0|
|2|2|2→2|0→0|
|3|1|1→1|0→0|
|4|2|1→2|1→1|
|5|1|1→1|1→1|
|6|1|0→1|1→1|
|7|1|0→1|1→1|

总计后继产出5/11→10/11。剩余case0地块实际资源到齐时已续种新小麦，赶不上截止时点；没有强行清除未成熟作物或虚构资源使其完成。

case1 自己现金54,702→55,667，对手54,655→55,972，因而由胜变负。更可靠地执行一个差选择，仍然是差选择。现金上涨不能代替比赛收益。

注意：本次最终干预的旧诊断日志首行 `choice` 打印的是归档选择（handoff=false）；`summary.reports[].intervention=true` 与实际batch的route_handoff才表示干预。诊断输出已修正为同时记录 archived_choice 与真正执行的 choice，已有审计原文件保留不改。

## 对训练下一步的约束

原数据延期方案311次对照中27次改善、83次退步；立即方案308次中26次改善、52次退步。当前菜单还按公开商店、日期轮换优先给动物延期/立即安排占位。它提供时序覆盖，却没有证明这些方案适合当前局面；不采用这些方案可能符合数据。

下一步应先在已修正执行器下，比较同一局面的续种、转其他作物、少量转养、延后这几类真实可行安排，检查是否存在足够的胜负改善机会及可见条件差异。品种/规模不能仅由日期轮换决定；候选预测只能用于提案，标签仍来自真实终局。随后才检查网络能否在未见种子选中这些安排。

本轮没有修改上述候选排序，也没有证明模型泛化改善；避免同时改执行、菜单和训练算法而失去归因。没有启动训练。此次修正可保留为执行基础，不能作为长训有效的承诺。
